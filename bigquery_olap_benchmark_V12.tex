\textbf{\color{springerblue}Abstract}\\[0.3em]
\textbf{Background:} Hybrid analytical SQL engines spanning serverless cloud warehouses, vectorized CPUs (C++ DuckDB, Rust Polars/DataFusion), and discrete GPUs exhibit sharp latency and memory crossovers where static engine selection or simple rules incur severe PCIe transfer stalls and out-of-core spilling.

\textbf{Objective:} We characterize physical PCIe/VRAM and memory-wall crossover laws across four hardware archetypes ($\text{SF}\in\{1,10,30,100\}\text{ GB}$) and evaluate \textbf{AST-Route}, a pre-execution SQL guard that bounds 95th-percentile (P95) tail regret without compiling physical query plans.

\textbf{Methods:} AST-Route pairs a 9D AST+zone-map vector ($\mathbf{x}_q^{\text{scale}}\in\mathbb{R}^{10}$ across scales), boosted trees, tier-stratified Mondrian conformal bounds, and a pre-specified inner-fold nested-CV PCIe margin guard ($\hat{\tau}_{\text{guard}}^{(-k)}=8\%$). We evaluate $400$ benchmark queries, $80$ public real-world/trace queries (SDSS DR16, NYC TLC, and Amazon Redshift \texttt{Redset} at $\text{SF}=10\text{ GB}$), and $70$ schema-blinded stress queries across $G_{\text{total}}=42$ template families, benchmarking against five GPU modes (cold FP64, pinned+async-overlap FP64/FP32, resident-VRAM, and native \texttt{RAPIDS cuDF} / RMM-pooled \texttt{cudf-polars}).

\textbf{Results:} Three-way ablation shows the $8\%$ margin guard drives in-domain P95 tail reduction ($-78.2\text{ pp}$), Mondrian bounds protect under distribution shift ($-48.6\text{ pp}$, $p=0.0018$), and oblique $\text{CSCI}$ prunes $-28.2\%$ of tree splits while lifting zero-shot cross-schema Top-1 by $+6.1\text{--}12.5\text{ pp}$. On Core 75Q ($\text{SF}=1\text{ GB}$), AST-Route matches static GPU mean latency ($55.37\text{ vs.\ }56.96\text{ ms}$, non-inferiority $p_{\text{Holm}}=0.0048$), beats Polars by $1.49\times$ ($p_{\text{Holm}}=0.0084$), and cuts P95 regret by $2.13\times\text{--}2.77\times$ across cold, pinned-overlap FP64/FP32, and RMM-pooled \texttt{cudf-polars} ($p_{\text{Holm}}=0.0136$; $56.00\%$ Top-1, $76.00\%$ Top-2), where a 2-engine $\{\text{Polars},\text{GPU}\}$ pool captures $98.7\%$ of the 6-engine gain. Across $G_{\text{total}}=42$ template families ($N=312$), linear mixed-effects modeling confirms a $-62.06\text{ pp}$ regret reduction ($p<10^{-15}$). In multi-scale router-in-the-loop dispatch ($\text{SF}=10\text{--}100\text{ GB}$), AST-Route achieves $90.91\%\text{--}95.45\%$ Top-1 ($0.00\%$ P95 regret) on Tesla~T4 ($2.85\times\text{--}9.50\times$ intra-node GPU speedups across $\text{SF}=1\text{--}100\text{ GB}$, $7.43\times\text{--}9.50\times$ at $\text{SF}=10\text{--}100\text{ GB}$) and $90.00\%\text{--}92.00\%$ Top-1 on $\text{SF}=10\text{ GB}$ public SDSS, NYC TLC, and \texttt{Redset} workloads.

\textbf{Conclusion:} Pre-execution PCIe/VRAM guarding and conformal AST routing provide predictable tail-risk insurance across heterogeneous OLAP environments.

\noindent\textbf{Keywords:} Cross-engine query routing; Tail-risk control; Conformal prediction; Heterogeneous OLAP systems; Apache Arrow and GPU analytics; Multi-objective cost modeling

\section{Introduction}
Modern enterprise analytics increasingly operate over heterogeneous, polyglot data infrastructures spanning four distinct computing paradigms: elastic serverless cloud data warehouses such as Google BigQuery \cite{melnik2010dremel, melnik2020dremel, lounissi2025funda}, in-process C++ vectorized analytical database systems such as DuckDB \cite{raasveldt2019duckdb, kuiper2024duckdb_ooc}, Rust-based Apache Arrow streaming query engines such as Polars and Apache DataFusion \cite{lamb2024datafusion}, and SIMT GPU-accelerated relational engines \cite{chrysogelos2019hetexchange, shanbhag2020crystal, bress2013hype}, alongside distributed multi-node systems like ClickHouse \cite{schulze2024clickhouse} and Trino \cite{sethi2019presto}. While cloud-native disaggregated storage-compute architectures provide massive horizontal slot concurrency for petabyte-scale workloads \cite{shojaee2024serverless, abdalla2022bigdata}, they introduce non-trivial stateless scheduling and distributed shuffle overheads on moderate-scale datasets \cite{begoli2018calcite, garcia2008database, lounissi2025funda}. Concurrently, modern local hardware presents an intricate architectural trade-off between CPU SIMD vectorization over Apache Arrow memory buffers and discrete GPU offloading across the PCIe interconnect \cite{milicevic2024dlquery, root2019mapd, kim2022blazingsql}.

Because each execution paradigm exhibits fundamentally different algorithmic strengths and memory-hierarchy bottlenecks across the discrete scale factors defined by the Transaction Processing Performance Council ($\text{SF} \in \{1, 10, 30, 100\text{ GB}\}$ in the TPC-H specification \cite{tpc2022tpch, boncz2014tpch, dreseler2020quantifying}), committing an entire analytical workload to any single static engine results in severe performance regret, excessive energy consumption, out-of-core spilling penalties, or unnecessary cloud FinOps expenditure. Designing an automated, pre-execution query routing framework capable of dynamically dispatching SQL queries to their optimal execution backend requires overcoming three critical research gaps in the existing literature \cite{ahmed2020hibench, oneil2009ssb, leis2015job}:
\begin{itemize}[leftmargin=1.5em,itemsep=2pt]
    \item \textbf{Research Gap 1 (Limitations of Single-Engine Learned Optimizers, Cloud Predictors, and Plan-Dependent Polystore Routers):} Existing learned query optimizers such as Neo \cite{marcus2019neo} and Bao \cite{marcus2021bao} steer physical operator plans \emph{within} a single database engine, Zero-Shot Cost Models \cite{hilprecht2022zeroshot} require physical execution plan graphs, cloud stage predictors \cite{ganapathi2009predicting, nathan2024stage} estimate runtimes within a single cloud warehouse, and cross-platform/polystore optimizers such as BigDAWG \cite{tan2023stage} and RHEEM / Apache Wayang \cite{gupta2023adaptive} require compiling query sub-plans into platform-specific operator DAGs using calibrated point-estimate cost functions without modeling Apache Arrow vs.\ PCIe GPU transfer thresholds or distribution-free conformal tail-risk bounds. A lightweight pre-execution framework that extracts static Abstract Syntax Tree (AST) features and zone-map selectivity directly from raw SQL to route queries across C++ DBMS, Rust Arrow, CUDA GPU, and serverless cloud paradigms remains underdeveloped.
    \item \textbf{Research Gap 2 (Unmodeled PCIe Crossover Thresholds, Memory Walls, and Device-Level Energy Costs):} Prior GPU database studies \cite{shanbhag2020crystal, root2019mapd, kim2022blazingsql} predominantly report warm in-VRAM kernel speedups at fixed small scale factors ($\text{SF}=1\text{ GB}$) while omitting cold-start PCIe Host-to-Device (H2D) transfer overheads, chunked PCIe streaming when datasets exceed device VRAM ($\text{SF}=10, 30, \text{and } 100\text{ GB}$), out-of-core host RAM disk spilling \cite{kuiper2024duckdb_ooc}, and hardware energy efficiency ($\text{Joules}$ and $\text{MB/J}$).
    \item \textbf{Research Gap 3 (Confounded Complexity, Data Leakage, and Lack of Nested Cross-Workload Validation):} Traditional OLAP evaluations \cite{ahmed2020hibench, abdalla2022bigdata} rely on unstratified query sets where structural operator depth, storage layout (row-store vs. Parquet vs. Arrow), and predicate selectivity are confounded, and where random train-test splits across variations of the same query template induce severe data leakage without testing generalization to unseen seeds, join-crossing skew correlations \cite{boncz2017jcch}, or nested cross-validation on standard TPC-H Q1--Q22 choke-point workloads \cite{boncz2014tpch, dreseler2020quantifying}.
\end{itemize}

\par\vspace{7pt plus 2pt minus 1pt}\noindent\textbf{Bridging Memory-Wall Big Data Orchestration, Crossover Profiling, and Risk-Aware Routing.}
In modern hybrid analytics, "Big Data" scale is defined not solely by petabyte cluster volume, but by the ratio of query working-set footprint to local memory-hierarchy capacity ($\mathcal{B}_{\text{work}}(q)/M_{\text{cap}} \in [0.05\times, 6.25\times]$, spanning in-VRAM execution at $\text{SF}=1\text{ GB}$, out-of-VRAM PCIe chunked streaming at $\text{SF}=10\text{--}30\text{ GB}$, and heavy out-of-core NVMe spilling vs.\ elastic serverless cloud offloading at $\text{SF}=100\text{ GB}$ [$866.1\text{M}$ rows]). Designing a reliable cross-paradigm dispatcher across this continuum requires resolving a fundamental systems tension: static single-engine policies suffer severe performance cliffs across heterogeneous operators, yet naive point-estimate cost minimization (unconstrained $\arg\min$ over predicted latency $\hat{T}_e(q)$) triggers costly tail-latency spikes whenever prediction intervals overlap near CPU--GPU PCIe crossover boundaries or device memory ceilings. Rather than treating hardware benchmarking and learned routing in isolation, this study grounds an interpretable, zero-execution routing architecture directly in controlled factorial crossover telemetry within a well-defined hardware envelope ($4.0\text{ GB}$ PCIe Gen4 discrete GPU, $16\text{ GB}$ host DRAM with $9.0\text{ GB}$ DBMS cap, cross-checked on 22-thread \texttt{x86\_64} and Apple M1 \texttt{ARM64} nodes). Crucially, decoupling the pre-execution structural/volume representation ($\mathbf{x}_q \in \mathbb{R}^9$, extended to $\mathbf{x}_q^{\text{scale}}\in\mathbb{R}^{10}$) from the downstream decision policy exposes an explicit operational trade-off between \emph{unconstrained mean-latency minimization} and \emph{tail-safe SLA protection} (governed via calibrated conformal prediction intervals and resource-constrained Pareto dispatch). Detailed metrics, negative results, and scope boundaries are consolidated in Additional File~1 (Table~S22), organized around three concise contributions:
\begin{enumerate}[leftmargin=1.5em,itemsep=1.5pt]
    \item \textbf{Contribution 1 --- Empirical Four-Node PCIe/VRAM Crossover Laws \& Three-Way Tail-Safety Decomposition (\texttt{Guard} vs.\ \texttt{+Conformal} vs.\ \texttt{+CSCI}):} Across four hardware nodes ($\text{SF}\in\{1,10,30,100\}\text{ GB}$) and $\mathbf{400}$ benchmark queries in four epistemic categories ($\mathbf{75}$ \emph{Cat~I Core}, $\mathbf{55}$ \emph{Cat~II Diagnostic} [$22$ TPC-H $+$ $33$ JOB], $\mathbf{115}$ \emph{Cat~III Derived}, and $\mathbf{155}$ \emph{Cat~IV Untouched Standard} [$99$ Official TPC-DS $+$ $43$ ClickBench $+$ $13$ SSB]; Section~\ref{sec:layer1_ast_taxonomy}, Additional File~1 Table~S18), we formalize physical PCIe transfer versus SIMT compute crossover laws and show why five simple heuristics (\texttt{H1--H5}, Table~\ref{tab:routing_evaluation}: $307.55\%\text{--}413.69\%$ P95 regret) suffer severe tail stalls. Crucially, rather than claiming that learned routing universally dominates every component in isolation, our \textbf{Three-Way Stepwise Ablation} (Table~\ref{tab:jbd_ablation_t9} Exp~D) isolates each mechanism's exact contribution and 95\% cluster confidence interval: (i) adding the \textbf{PCIe Margin Threshold Guard alone ($\tau_{\text{guard}}=8\%$)} to an 8D Raw-AST model cuts in-domain P95 regret from $214.60\%\rightarrow \mathbf{136.40\%}$ ($\Delta\text{P95}=\mathbf{-78.20\text{ pp}}$, 95\% CI $[-142.5,-24.8]\text{ pp}, p_{\text{Webb}}=0.0082$), demonstrating that $\mathbf{81.3\%}$ of the in-domain P95 tail reduction is driven by the threshold guard itself (and a minimalist 2-engine $\{\text{Polars},\text{GPU}\}$ pool at $55.28\text{ ms}$ captures $\mathbf{98.7\%}$ of the 6-engine gain at $\text{SF}=1\text{ GB}$); (ii) adding \textbf{Tier-Stratified $90\%$ Mondrian Conformal Bounds} yields a modest additional in-domain P95 shift ($-11.60\text{ pp}$ to $124.80\%$), but cuts $\text{CVaR}_{10\%}$ by $-31.4\text{ pp}$ and reduces P95 regret under \textbf{selectivity/distribution drift and cloud spill gating} by $\mathbf{-48.60\text{ pp}}$ (95\% CI $[-76.2,-21.4]\text{ pp}, p=0.0018$); and (iii) adding the \textbf{oblique structural projection $\text{CSCI}(q)$} ($\operatorname{Var}(\text{CSCI}\mid D..C)=0$) compresses depth-3 GBDT trees by $\mathbf{-28.2\%}$ ($6.84\rightarrow 4.91$ splits/tree), lowers in-domain mean regret by $\mathbf{-5.40\text{ pp}}$ ($41.20\%\rightarrow 35.80\%, p=0.0038$), and improves zero-shot cross-schema Top-1 accuracy by $\mathbf{+4.0\text{ to }+7.5\text{ pp}}$ on held-out multi-table suites.
    \item \textbf{Contribution 2 --- Evaluation Against Five Stronger GPU Baselines, Single Pre-Specified Primary Guard, and $G_{\text{total}}=42$ Template-Cluster Mixed-Effects Inference:} To avoid straw-man GPU comparisons, we benchmark against five progressively stronger GPU architectures on physical hardware (Table~\ref{tab:six_software_matrix} and Table~\ref{tab:routing_evaluation}): \textbf{(B1) Cold Single-Stream FP64} ($56.96\text{ ms}$, $257.31\%$ P95), \textbf{(B2) Pinned Host RAM (\texttt{cudaHostAlloc}) + 2-Stream Asynchronous H2D/Compute Double-Buffered Overlap FP64} ($47.82\text{ ms}$, $189.40\%$ P95 $\rightarrow$ AST-Route $\mathbf{44.18\text{ ms}}$ exec / $\mathbf{48.33\text{ ms}}$ net, $\mathbf{86.20\%}$ P95, $\mathbf{2.20\times}$ cut, $p_{\text{Webb}}=0.0048$), \textbf{(B3) Pinned + Async Overlap FP32} ($39.64\text{ ms}$, $154.20\%$ P95 $\rightarrow$ AST-Route $\mathbf{37.95\text{ ms}}$ exec / $\mathbf{42.10\text{ ms}}$ net, $\mathbf{72.40\%}$ P95, $\mathbf{2.13\times}$ cut), \textbf{(B4) Pre-Loaded Resident-VRAM Warm Cache} ($22.25\text{ ms}$, winning $90.67\%$ of queries at $\text{SF}=1\text{ GB}$ where static GPU suffices, before overflowing the $4.0\text{ GB}$ VRAM cap at $\text{SF}\ge 10\text{ GB}$), and \textbf{(B5) Native GPU Execution Engines (\texttt{RAPIDS cuDF libcudf v26.06.00} \& $2.5\text{ GB}$ RMM-Pooled \texttt{cudf-polars v26.10.2 C3})} ($63.82\text{ ms}$ RMM $\rightarrow$ AST-Route $\mathbf{52.74\text{ ms}}$ exec / $\mathbf{56.89\text{ ms}}$ net, cutting P95 regret by $\mathbf{2.77\times}$ from $338.00\%\rightarrow \mathbf{121.84\%}, p_{\text{Webb}}=0.0042$). To eliminate forking-path ambiguity, we lock the \textbf{inner-fold Nested-CV guard ($\hat{\tau}_{\text{guard}}^{(-k)}=8\%$)} as our \textbf{sole primary endpoint} (reporting fixed $\tau_{\text{guard}}=12\%$ [$54.92\text{ ms}$ net, $114.11\%$ P95] strictly as a secondary sensitivity point) and enforce **Global Holm--Bonferroni Multiplicity Control** across a 4-hypothesis primary family $\mathcal{F}_{\text{primary}}$ ($H_1$ P95 cut vs.\ GPU $p_{\text{Holm}}=0.0136$; $H_2$ $1.49\times$ speedup vs.\ Polars $p_{\text{Holm}}=0.0084$ [$p_{\text{Holm,query}}=0.0011, p_{\text{Holm,seed}}=0.0171$]; $H_3$ $+10\%$ non-inferiority vs.\ GPU $p_{\text{Holm}}=0.0048$ [exploratory $\pm 5\text{ ms}$ TOST $p_{\text{TOST}}=0.0442$]; and $H_4$ vs.\ Unguarded Ridge $p_{\text{Holm}}=0.0464$, which is borderline at $G_{\text{core}}=10$ with wide CI $[-225.12,-2.84]\text{ pp}$, while Guarded Ridge $+12\%$ [$p_{\text{Webb}}=0.3840$] and EXPLAIN-DAG [$p_{\text{Webb}}=0.7420$, $-5.84\text{ ms}$ slower net] match on P95). Expanding across $\mathbf{G_{\text{total}}=42}$ \textbf{independent template-family clusters ($N=312$ queries)} via a **Hierarchical Linear Mixed-Effects (LME) Model** (Table~\ref{tab:v11_r23_r22_energy_and_dynamic_sla}) confirms a $-62.06\text{ pp}$ regret reduction ($\text{SE}=1.08\text{ pp}, z=-57.37, p<10^{-15}$), while query-level hardware energy correlation across all $N=75$ queries between directly measured \textbf{Scope~1 NVML GPU sensors} and \textbf{Scope~3 ACPI DC shunt} is $\mathbf{\rho_{N=75}=0.9684}$ ($p=1.4\times 10^{-45}$).
    \item \textbf{Contribution 3 --- Multi-Scale Router-in-the-Loop ($\text{SF}=10\text{--}100\text{ GB}$), Public Fleet Trace Validation (\texttt{Redset}, SDSS DR16, NYC TLC at $\text{SF}=10\text{ GB}$), and Failure Taxonomy:} Addressing the Big Data scale requirement directly, we execute \textbf{Router-in-the-Loop dispatch across $\text{SF}\in\{10,30,100\}\text{ GB}$} (where query runtimes are $180\text{--}27{,}200\text{ ms}$ and the $4.15\text{ ms}$ cold router overhead is $<0.02\%\text{--}2.3\%$): on Node~1, AST-Route achieves $\mathbf{182.40\text{ ms}}$ ($\text{SF}=10\text{ GB}$, $5.21\times$ vs.\ DuckDB), $\mathbf{448.65\text{ ms}}$ ($\text{SF}=30\text{ GB}$, $5.78\times$), and $\mathbf{1{,}142.80\text{ ms}}$ ($\text{SF}=100\text{ GB}$, $7.61\times$, offloading $20\%$ NVMe-spilling queries to BigQuery); on Node~4 Cloud-Hosted Server NVIDIA Tesla~T4 ($15.0\text{ GB}$ VRAM), zero-leakage \textbf{\texttt{LOTFO}} on Official TPC-H Q1--Q22 achieves $\mathbf{90.91\%\text{--}95.45\%}$ Top-1 and $\mathbf{0.00\%}$ P95 regret at $\text{SF}=10\text{ and }30\text{ GB}$ ($622.38\text{ and }1{,}905.61\text{ ms}$ net, shifting GPU share from $59.09\%\rightarrow 81.82\%\rightarrow 86.36\%$), while 4-node $\text{SF}=100\text{ GB}$ scan-filter-aggregation with \texttt{RAPIDS cuDF} and \texttt{cudf-polars} ($2.85\times\text{--}9.50\times$ intra-node speedups across $\text{SF}=1\text{--}100\text{ GB}$, $7.43\times\text{--}9.50\times$ at $\text{SF}=10\text{--}100\text{ GB}$) demonstrates cross-node crossover where 22-thread Node~2 Polars ($4{,}266.59\text{ ms}$) surpasses 10-chunk \texttt{cudf-polars} ($5{,}279.66\text{ ms}$). On multi-GB \textbf{Official TPC-DS}, AST-Route achieves $\mathbf{83.64\%}$ Top-1 at $\text{SF}=1\text{ GB}$ ($55$Q, $64.60\text{ ms}$) and $\mathbf{86.67\%}$ Top-1 at $\text{SF}=10\text{ GB}$ ($30$Q, $164.20\text{ ms}$, $2.34\times$ vs.\ Polars; with $\text{SF}=0.02$ $99$Q retained as a syntax-compatibility baseline at $64.65\%$ Top-1 / $84.85\%$ Pure-SQL). Furthermore, scaling $\mathbf{50}$ \textbf{Public SDSS SkyServer DR16 ($25$Q) and NYC TLC ($25$Q) queries} plus $\mathbf{30}$ \textbf{Public Amazon Redshift \texttt{Redset} Fleet Trace queries}~\cite{vanrenen2024redset} to $\mathbf{\text{SF}=10\text{ GB}}$ ($25\text{M}$ rows, $209\text{--}246\text{ ms}$ in Regime~R3/R4) yields $\mathbf{90.00\%\text{--}92.00\%}$ Top-1, $\mathbf{100.0\%}$ Top-2, and cuts GPU P95 regret from $300\%+$ to $\mathbf{7.80\%\text{--}9.00\%}$ (distinct from our $70$ author-constructed stress queries at $95.71\%$ Top-1 and the sub-$10\text{ ms}$ $1\text{M}$-row Regime~R1 diagnostic at $90.00\%$ Top-1). Finally, we provide a complete \textbf{Misrouted Query Failure Taxonomy (\texttt{F1--F3})}, \textbf{Exact TreeSHAP Attribution} ($\hat{\sigma}=34.2\%, \text{CSCI}=24.8\%, J=14.6\%$), and practitioner break-even matrix (Table~\ref{tab:when_to_use_breakeven}).
\end{enumerate}

\section{Related Work and Architectural Representativeness}
\noindent\textbf{Section Takeaway:} \emph{Prior intra-DBMS learned optimizers (Neo, Bao, Lero) and plan-based cost models (Zero-Shot, Stage) require compiled physical operator DAGs within a single engine, whereas GPU engines (Crystal, Sirius, RAPIDS cuDF) omit pre-execution conformal tail-risk guards against PCIe transfer stalls. AST-Route bridges this gap via zero-plan raw-SQL AST + zone-map routing across CPU, GPU, and cloud paradigms (Table~\ref{tab:related_work_comparison}).}\par\vspace{2pt}
\subsection{Cloud MPP Warehouses, Distributed Query Engines, and Vectorized CPU Systems}
Disaggregated cloud data warehouses pioneered by Google Dremel/BigQuery \cite{melnik2010dremel, melnik2020dremel} and distributed MPP query engines such as Presto/Trino \cite{sethi2019presto}, ClickHouse \cite{schulze2024clickhouse}, and Apache Spark \cite{ahmed2020hibench} decouple compute workers from durable storage. Recent studies in serverless data pipelines \cite{shojaee2024serverless} and in-situ serverless query processing such as FunDa \cite{lounissi2025funda} highlight the fundamental tension between cold-start scheduling overhead and horizontal slot elasticity. Specifically, while Trino \cite{sethi2019presto} excels at federated cross-source query execution over distributed object stores and ClickHouse \cite{schulze2024clickhouse} achieves high throughput via shared-nothing merge-tree storage and SIMD vectorization across cluster nodes, both introduce network serialization and coordinator scheduling overheads when deployed on single-node or moderate-scale datasets. Conversely, embeddable C++ vectorized engines such as DuckDB \cite{raasveldt2019duckdb, kuiper2024duckdb_ooc} process columnar Row Groups in-process using morsel-driven parallelism and out-of-core external memory management, whereas next-generation Rust engines (Polars and Apache DataFusion \cite{lamb2024datafusion}) execute zero-copy SIMD and streaming pipelines directly over standardized Apache Arrow memory buffers.

\subsection{GPU-Accelerated Databases, Learned Query Optimizers, and Adaptive Query Routing}
In the domain of GPU-accelerated relational analytics, systems such as HeavyDB (formerly OmniSci/MapD) \cite{root2019mapd}, BlazingSQL over RAPIDS cuDF \cite{kim2022blazingsql}, Crystal \cite{shanbhag2020crystal}, and HetExchange \cite{chrysogelos2019hetexchange} leverage massive SIMT parallelism and high-bandwidth device memory (VRAM) to accelerate relational joins and group-by aggregations. However, as demonstrated by Chrysogelos et al. \cite{chrysogelos2019hetexchange} and Shanbhag et al. \cite{shanbhag2020crystal}, discrete GPU execution is fundamentally constrained by the PCIe interconnect when data resides in host DRAM or exceeds device VRAM capacity, necessitating rigorous separation of PCIe transfer latency from kernel compute time.

Concurrently, recent surveys on deep learning in query execution \cite{milicevic2024dlquery} and learned query optimization have advanced along three distinct trajectories: (i) \emph{Intra-DBMS Plan Steering, Relative Plan Ranking, and Parametric Plan Robustness} systems such as Neo \cite{marcus2019neo}, Bao \cite{marcus2021bao}, Lero \cite{zhu2023lero}, AutoSteer \cite{anneser2023autosteer}, and Kepler \cite{doshi2023kepler}, which use tree-convolutional neural networks to generate physical plans (Neo), select contextual-bandit hint sets (Bao), learn pairwise relative plan rankings without absolute cardinality labels (Lero), discover active optimizer rule hints across SQL engines (AutoSteer), or enforce robust parametric plan selection under selectivity uncertainty (Kepler), yet operate strictly \emph{within} a single relational engine rather than routing across disparate CPU, GPU, and cloud paradigms; (ii) \emph{Learned Physical Cost Models} such as Zero-Shot Cost Models \cite{hilprecht2022zeroshot}, which generalize cost prediction across unseen single-node databases, yet still require compiled physical operator plan graphs and exact cardinalities rather than pre-execution raw SQL syntax; and (iii) \emph{Cross-Platform / Polystore Query Optimizers and Stage Routers} such as BigDAWG \cite{tan2023stage} and RHEEM / Apache Wayang \cite{gupta2023adaptive}, which decompose and dispatch compiled logical/physical sub-plans across heterogeneous data processing platforms (e.g., Spark, Java Streams, and PostgreSQL) using cost-based plan enumeration or historical execution logs, but require operator-graph compilation and do not combine zero-plan-compilation raw-SQL AST + zone-map dispatch with calibrated conformal tail-risk guards across local Rust Arrow, discrete PCIe GPU ($\Phi_{\text{PCIe}}$), and serverless cloud warehouses. To benchmark against published learned-optimizer paradigms empirically rather than only architecturally, we implement and evaluate cross-engine adaptations of both \textbf{Bao/AutoSteer-style contextual-bandit arm selection} (treating candidate engines as bandit arms over 9D features via Thompson-sampled tree ensembles) and \textbf{Zero-Shot / Stage / Lero-style physical-plan cost models} (extracting physical operator DAGs and estimated cardinalities via \texttt{DuckDB EXPLAIN (FORMAT JSON)} into GBR and MLP cost predictors, both natively and after cross-dialect \texttt{SQLGlot} transpilation). In parallel, the TPC-H decision support benchmark specification \cite{tpc2022tpch} establishes discrete scale factors ($\text{SF}=1, 10, 30, 100\text{ GB}$) and 22 canonical queries (Q1--Q22) whose internal execution choke points (multi-way join graphs in Q2, Q5, Q7, Q8, Q9, Q21 and correlated subqueries in Q16--Q22) have been formalized by Boncz et al. \cite{boncz2014tpch} and Dreseler et al. \cite{dreseler2020quantifying}. Complementing classical OLAP benchmarks such as SSB \cite{oneil2009ssb} and JOB \cite{leis2015job}, modern text-to-SQL benchmarks such as BIRD \cite{li2023bird} and Spider 2.0 \cite{lei2025spider2} incorporate the Valid Efficiency Score ($\text{VES}(q,e) = \mathbb{I}(\text{EX}(q,e)=1)\cdot\sqrt{T_{\text{ref}}(q)/T_e(q)}\times 100$, exceeding $100$ whenever $T_e(q) < T_{\text{ref}}(q)$), while AST transpilers such as \texttt{SQLGlot} \cite{mao2024sqlglot} and Apache Calcite \cite{begoli2018calcite} enable deterministic structural analysis. Most recently, modular heterogeneous execution engines such as Maximus~\cite{kabic2025maximus} and DuckDB-integrated GPU accelerators such as Sirius~\cite{yogatama2025sirius} have demonstrated substantial SIMT speedups when relational working sets fit within device HBM/VRAM, while energy-aware and risk-aware learned query optimization frameworks such as E-LQO~\cite{liang2026elqo} have highlighted the importance of energy telemetry and prediction uncertainty within single-engine optimizers. \subsection{Rationale for Target Execution Engines in the AST-Route Framework}
Rather than exhaustively evaluating every commercial DBMS, \textbf{AST-Route} targets six software engines that serve as canonical, non-redundant representatives of the four foundational execution paradigms in modern data engineering:
\begin{enumerate}[leftmargin=1.5em,itemsep=0.8pt]
    \item \textbf{SQLite 3 (Canonical Tuple-at-a-Time B-Tree Row-Store Reference Baseline):} Represents traditional ANSI C row-oriented storage using a Volcano-style iterator model, establishing the exact performance ($8417.33\text{ ms}$ at $\text{SF}=1\text{ GB}$) and energy baseline of B-tree page traversal without columnar compression or SIMD vectorization. Because columnar CPU and GPU engines strictly dominate B-tree row-store scans on $100\%$ ($75/75$) of analytical queries, SQLite~3 receives a $0.0\%$ selection share in active routing while remaining in the six-engine benchmark matrix as the canonical row-store reference.
    \item \textbf{Google BigQuery (Canonical Serverless Disaggregated Cloud OLAP --- Multi-Scale Spill Offload Target):} Represents petabyte-scale cloud-native execution (Dremel/Capacitor columnar storage with dynamic slot allocation) \cite{melnik2020dremel}, isolating distributed cloud orchestration overhead and storage clustering FinOps economics. Crucially, at $\text{SF}=1\text{--}30\text{ GB}$, BigQuery's latency ($745.39\text{ ms}$ server execution at $\text{SF}=1\text{ GB}$) reflects a \emph{serverless multi-tenant scheduling and metadata floor} rather than scan throughput; accordingly, BigQuery is not included as a straw-man latency competitor for in-memory queries ($0.0\%$ routing share at $\text{SF}=1\text{--}30\text{ GB}$), but is retained across all four scale factors ($\text{SF}\in\{1,10,30,100\}\text{ GB}$) to pinpoint the exact memory-wall crossover at $\text{SF}=100\text{ GB}$ where local CPU engines suffer severe out-of-core NVMe disk spilling ($3{,}302\text{ MB}$ spill, $6{,}551\text{--}8{,}700\text{ ms}$) and cloud offloading ($2{,}571.6\text{ ms}$ server / $3{,}356.2\text{ ms}$ WAN) becomes latency-optimal for spill-bound queries.
    \item \textbf{DuckDB (Canonical C++ Morsel-Driven Columnar DBMS):} Represents state-of-the-art in-process C++ analytical database design \cite{raasveldt2019duckdb, kuiper2024duckdb_ooc} with tightly integrated storage block management, parallel segment-tree window framing, and out-of-core external disk spilling.
    \item \textbf{Polars \& Apache DataFusion (Canonical Rust Apache Arrow Engines):} Represent the emerging Rust Arrow ecosystem via two distinct optimizer philosophies: \emph{Polars} exemplifies a dataframe-native lazy streaming engine over Arrow arrays, whereas \emph{Apache DataFusion} \cite{lamb2024datafusion} exemplifies a modular SQL physical query planner (used as the core execution engine in modern distributed systems such as InfluxDB 3.0 and Ballista).
    \item \textbf{Author-Developed PyTorch CUDA Relational Tensor Execution Backend (Compiled SIMT GPU Prototype):} Unlike DuckDB, DataFusion, SQLite, or BigQuery---which are standalone SQL database engines with integrated SQL parsers and query planners---this backend is an \emph{author-developed relational tensor execution prototype} built on PyTorch ATen/CUDA kernels over contiguous VRAM buffers (architecturally analogous to the operator kernels in BlazingSQL \cite{kim2022blazingsql} and Crystal \cite{shanbhag2020crystal}). Because our experimental testbed targets a tight $4.0\text{ GB}$ physical VRAM ceiling ($3.2\text{ GB}$ usable buffer on the laptop RTX~2050) that requires custom $4\times\text{--}40\times$ PyArrow-to-VRAM chunked streaming at $\text{SF}=10\text{--}100\text{ GB}$ and explicit hardware instrumentation of PCIe Gen4 H2D/D2H DMA transfer versus SIMT kernel execution (whereas monolithic GPU SQL engines such as HeavyDB \cite{root2019mapd}, RAPIDS cuDF \cite{kim2022blazingsql}, and Sirius \cite{yogatama2025sirius} target larger server-grade VRAM pools without exposing fine-grained 7-stage PCIe/kernel timers across out-of-VRAM chunks), this prototype compiles six core relational algebra operators (projection, boolean mask filtering, radix hash-join, segmented group-by, bitonic/radix sort, and prefix-scan window/unnest expansion) from \texttt{SQLGlot} AST plans. To ensure that AST-Route's scientific contribution never depends on backend implementation differences between compiled tensor kernels and SQL parsers, we enforce a three-level GPU timing protocol ($22.25\text{ ms}$ Level-1 Warm Kernel, $56.96\text{ ms}$ Level-2 Cold In-Memory PCIe+Kernel, and $61.11\text{ ms}$ Level-3 Full SQL-to-Result with $+4.15\text{ ms}$ lowering; $131.79\text{ ms}$ from cold on-disk Parquet) and evaluate \textbf{Pure Native-SQL Routing ($\mathcal{E}_{\text{SQL-Only}}$, $0\%$ GPU prototype)} across all three hardware nodes and all seven benchmark suites as a parallel primary finding (Section~\ref{sec:v852_reviewer_audit} and Additional File~1 (Table~S17)).
\end{enumerate}

\section{The Proposed AST-Route Framework Architecture}
\noindent\textbf{Section Takeaway:} \emph{AST-Route operates in four pre-execution layers ($4.15\text{ ms}$ cold / $0.08\text{ ms}$ cached): Layer~1 extracts a 9D AST + zone-map vector with oblique complexity index $\text{CSCI}(q)$; Layer~2 models PCIe crossover ($\Phi_{\text{PCIe}}$), Scope~1 NVML GPU energy, and cloud FinOps costs; Layer~3 computes complexity-weighted Mondrian $90\%$ conformal bounds and Mahalanobis OOD gates; and Layer~4 dispatches queries under parallel $8\%/12\%$ PCIe guards and Pareto policies P1--P4.}\par\vspace{2pt}
As illustrated in Fig.~\ref{fig:proposed_ast_framework} and the end-to-end validation workflow in Fig.~\ref{fig:experimental_workflow}, \textbf{AST-Route} is structured as a modular four-layer architecture that decouples static query representation from multi-paradigm hardware cost modeling and automated engine dispatching.

\subsection{Layer 1: Static AST Structural Profiling, Five-Tier Workload, and Official TPC-H Scale Tiers ($\text{SF}=1, 10, 30, 100\text{ GB}$)}
\label{sec:layer1_ast_taxonomy}\label{sec:workload_design}
Given an incoming SQL query $q \in \mathcal{Q}$, Layer 1 parses the SQL statement into a canonical Abstract Syntax Tree (AST) using \texttt{SQLGlot} \cite{mao2024sqlglot} without touching underlying data pages. Traversing the AST yields seven structural operator dimensions: tree depth $D(q)$, total AST operator nodes $N(q)$, relational join count $J(q)$, nested CTE/subquery depth $S(q)$, window frame specifications $W(q)$, repeated field unnesting operators $U(q)$, and conditional \texttt{CASE} branches $C(q)$. While total AST node count $N(q)$ captures overall query verbosity (and is retained directly as the second coordinate in our 9D routing vector $\mathbf{x}_q$), raw node counts are dominated by scalar expressions and projection lists that exhibit high collinearity with tree depth. To isolate the non-linear algorithmic complexity of relational operators without expression-length inflation, we formulate the Composite Structural Complexity Index ($\text{CSCI}$) over the six core structural operators:
\begin{equation}
    \text{CSCI}(q) = 1.5 D(q) + 2.5 J(q) + 3.0 S(q) + 3.5 W(q) + 4.0 U(q) + 1.5 C(q)
\end{equation}
In accordance with the official TPC-H benchmark specification Clause 4.1.3 \cite{tpc2022tpch} and established multi-scale choke-point methodologies \cite{boncz2014tpch, dreseler2020quantifying, kuiper2024duckdb_ooc}, we provision the 8-table TPC-H relational schema across four standard discrete scale factors designed to systematically stress every layer of the modern memory hierarchy:
\begin{itemize}[leftmargin=1.5em,itemsep=2pt]
    \item \textbf{$\text{SF}=1\text{ GB}$ (In-VRAM \& In-DRAM Baseline Regime):} Contains $6.00\times 10^6$ \texttt{lineitem} rows ($8.66\times 10^6$ total rows across 8 tables). The working set fits entirely within both the $4.0\text{ GB}$ discrete GPU VRAM buffer ($1.30\text{ GB}$ peak) and the $16.0\text{ GB}$ host DRAM ($4.71\text{ GB}$ peak) with zero disk spilling.
    \item \textbf{$\text{SF}=10\text{ GB}$ (Out-of-VRAM GPU Streaming \& In-DRAM Host Regime):} Contains $60.0\times 10^6$ \texttt{lineitem} rows ($86.6\times 10^6$ total rows). Uncompressed working projections exceed the $4.0\text{ GB}$ GPU VRAM ceiling, forcing 4-chunk pipelined PCIe H2D streaming ($3.45\text{ GB}$ peak VRAM) while remaining primarily in host DRAM ($7.85\text{ GB}$ peak RAM, $125.0\text{ MB}$ minor spill).
    \item \textbf{$\text{SF}=30\text{ GB}$ (Host DRAM Cap Inflection \& Moderate Out-of-Core Spill Regime):} Contains $180.0\times 10^6$ \texttt{lineitem} rows ($259.8\times 10^6$ total rows) \cite{tpc2022tpch}. Intermediate hash-join and window-sort partitions exceed the configured $9.00\text{ GB}$ host DBMS buffer pool cap, triggering active out-of-core disk spilling \cite{kuiper2024duckdb_ooc} ($864.0\text{ MB}$ mean spill) and 12-chunk GPU PCIe streaming ($3.68\text{ GB}$ peak VRAM).
    \item \textbf{$\text{SF}=100\text{ GB}$ (Extreme Out-of-Core Spilling \& Cloud Elasticity Crossover Regime):} Contains $600.1\times 10^6$ \texttt{lineitem} rows ($866.1\times 10^6$ total rows) \cite{tpc2022tpch, dreseler2020quantifying}, inducing heavy external disk spilling on local CPU engines ($3302.0\text{ MB}$ mean spill, peaking at $6840.0\text{ MB}$ in L2 joins) and 40-chunk PCIe transfers on the GPU ($3.85\text{ GB}$ peak VRAM).
\end{itemize}

Across this schema, we evaluate two complementary SQL workload suites: (A) our 75-query \emph{TPC-H-derived, AST-stratified synthetic analytical workload} instantiated from 25 canonical seeds across five modern structural complexity tiers ($5 \times 5 = 25$ independent seeds, mean $\text{CSCI} = 29.66$), and (B) the 22 \emph{official standard TPC-H benchmark queries} (\textbf{Q1--Q22}, mean $\text{CSCI} = 26.52$, range $12.0\text{--}47.5$) \cite{tpc2022tpch, boncz2014tpch}. Because the base TPC-H schema consists of flat relational tables, Tier L5 dynamically constructs nested array columns in-query via staged \texttt{ARRAY\_\allowbreak{}AGG} / \texttt{LIST} aggregation over one-to-many \texttt{orders}--\texttt{lineitem} relationships before benchmarking lateral \texttt{CROSS JOIN UNNEST} re-aggregation:
\begin{enumerate}[leftmargin=1.5em,itemsep=0.8pt]
    \item \textbf{L1 (Scan, SARGability, \& Monotonic Conditional Branching):} Single-table columnar scans with multi-branch \texttt{CASE WHEN} expressions and distinct cardinality aggregations ($D = 9.0, J = 0.0, \text{CSCI} = 15.3$).
    \item \textbf{L2 (Multi-Way Star, Snowflake, \& Bilateral Joins):} 4-way to 8-way relational joins, composite \texttt{partsupp} joins, and non-equi late-delivery predicates ($D = 9.2, J = 4.8, \text{CSCI} = 26.8$).
    \item \textbf{L3 (Multi-Stage CTE Pipelines, Null-Safe Anti-Joins, \& One-Grain-Per-CTE):} 3-stage to 4-stage Common Table Expressions enforcing pre-aggregated grain isolation and null-safe anti-joins ($D = 10.8, J = 2.6, \text{CSCI} = 36.7$).
    \item \textbf{L4 (Multi-Axis Window Ranking, Lead/Lag, \& Sliding Frames):} Concurrent window partitions (\texttt{RANK}, \texttt{DENSE\_\allowbreak{}RANK}, \texttt{NTILE(10)}, \texttt{LAG}, \texttt{LEAD}, and bounded \texttt{ROWS BETWEEN} sliding windows; $D = 10.8, J = 1.6, \text{CSCI} = 37.1$).
    \item \textbf{L5 (Semi-Structured Array Construction \& Lateral UNNEST):} Multi-stage \texttt{ARRAY\_\allowbreak{}AGG} vector construction followed by lateral \texttt{CROSS JOIN UNNEST} re-aggregation ($D = 10.6, J = 2.2, \text{CSCI} = 32.4$).
\end{enumerate}

To capture data-volume sensitivity alongside syntax topology without executing the query, each of the 25 canonical seeds is instantiated across three selectivity perturbation horizons ($25 \times 3 = 75$ queries): V1 (High Selectivity, $\sim 1\text{--}5\%$ data), V2 (Medium Selectivity, $\sim 15\text{--}30\%$ data), and V3 (Adversarial Full-Horizon, $\sim 65\text{--}95\%$ data). As detailed in Additional File~1 (Table~S1), Layer 1 extracts the pre-execution predicate selectivity estimate $\hat{\sigma}(q) \in (0, 1]$ in $172.0\text{ }\mu\text{s}$ from a pre-cached metadata snapshot ($412.6\text{ }\mu\text{s}$ cold footer read on Apache Parquet; $845.2\text{ }\mu\text{s}$ live \texttt{PRAGMA storage\_\allowbreak{}info} query on DuckDB) strictly prior to query execution without scanning data blocks or touching post-execution results. Crucially, we distinguish the exact metadata capabilities and limitations of each storage engine: (i) \emph{Parquet and DuckDB Row-Group Zone Maps}: \texttt{pyarrow.parquet.ParquetFile.metadata} and DuckDB \texttt{PRAGMA storage\_\allowbreak{}info('table')} expose column-level minimum, maximum, and null-count statistics across $100\%$ of numeric and date columns (e.g., \texttt{l\_\allowbreak{}shipdate} $\in [\texttt{1992-01-02}, \texttt{1998-12-01}]$, \texttt{l\_\allowbreak{}quantity} $\in [1.0, 50.0]$), enabling accurate range interpolation on both partitioned and non-partitioned numeric predicates (comparing estimated $\hat{\sigma}(q)$ against true post-execution row selectivity $\sigma_{\text{actual}}(q) = |R_{\text{out}}|/|R_{\text{table}}|$ yields a mean absolute error of $\text{MAE}=3.84\%$ and median Q-Error $=1.092$ (P90 $= 1.284$) across the 75-query suite, and $\text{MAE}=1.52\%$, Q-Error $=1.263$ on non-partitioned multi-attribute numeric predicates); (ii) \emph{BigQuery Partition Pruning Statistics}: \texttt{INFORMATION\_\allowbreak{}SCHEMA.}\newline\texttt{PARTITIONS} and dry-run byte estimation provide \emph{partition pruning and clustering statistics} (\texttt{partition\_\allowbreak{}id}, \texttt{total\_\allowbreak{}rows}, \texttt{total\_\allowbreak{}logical\_\allowbreak{}bytes}) rather than general column-level min/max zone maps for every attribute. When predicates filter on the partition key (\texttt{l\_\allowbreak{}shipdate}), partition pruning metadata estimates selectivity within $\text{MAE}=4.26\%$; however, on non-partitioned columns where BigQuery does not expose column-level min/max bounds, AST-Route either references the shared Parquet footer catalog or falls back to parametric AST operator priors (which we explicitly evaluate in Table~\ref{tab:ablation_robustness} Exp~C by masking $50\%$ of metadata, sustaining $53.33\%$ Top-1 accuracy and $68.42\text{ ms}$ mean latency); and (iii) \emph{String Predicates and Skewed Distributions}: because continuous min/max zone maps cannot bound unanchored substring filters (\texttt{LIKE '\%brass\%'}) or capture intra-range Zipfian skew ($s=1.2$), estimation error increases to $\text{MAE}=5.00\%$ (Q-Error $=2.000$) on substring predicates and $\text{MAE}=38.8\%$ (Q-Error $=4.880$) under severe power-law skew (explaining the $21.21\%$ Top-1 accuracy on string-skewed IMDB JOB queries in Table~\ref{tab:v9_sec3_5_tpcds_bird_external_validation} Part~C). Combining the seven static AST operator counts with $\text{CSCI}(q)$ and estimated selectivity $\hat{\sigma}(q)$ yields the 9-dimensional routing feature vector:
\begin{equation}
    \mathbf{x}_q = \big[\, D(q),\; N(q),\; J(q),\; S(q),\; W(q),\; U(q),\; C(q),\; \text{CSCI}(q),\; \hat{\sigma}(q) \,\big]^{\top} \in \mathbb{R}^{9}
\end{equation}
 We also provide a self-contained live production wrapper (\texttt{ASTRouteLiveSQLWrapper} in \texttt{scripts/v11\_ast\_route\_live\_sql\_wrapper\_demo.py}, logged in \texttt{results/v11\_live\_sql\_wrapper\_integration\_demo.csv}) that accepts an arbitrary raw SQL string and Parquet directory path, executes single-pass \texttt{sqlglot} AST extraction ($1.68\text{--}2.22\text{ ms}$), reads physical Parquet row-group min/max footers via \texttt{pyarrow.parquet.ParquetFile} ($0.13\text{--}0.16\text{ ms}$), evaluates the locked GBDT ensemble (\texttt{frozen\_ast\_route\_v11\_gbdt\_model.json}) with Mondrian conformal bounds ($0.48\text{--}0.51\text{ ms}$, total wrapper latency $\mathbf{2.29\text{--}2.89\text{ ms}}$), and dispatches the query to the selected engine while verifying exact BigQuery dry-run \texttt{totalBytesBilled} agreement ($100.0\%$ byte match). To avoid any ambiguity between representations, $\mathbf{x}_q \in \mathbb{R}^{9}$ serves as the sole feature vector for all fixed-scale ($\text{SF}=1\text{ GB}$) evaluations (Tables~\ref{tab:routing_evaluation}--\ref{tab:v11_r23_r22_energy_and_dynamic_sla} and Additional File~1, Table~S10), whereas the scale-augmented vector $\mathbf{x}_q^{\text{scale}} = [\mathbf{x}_q^{\top}, \log_{10}(1+\hat{\sigma}(q)\cdot\mathcal{B}_{\text{catalog}})]^{\top} \in \mathbb{R}^{10}$ is used exclusively in cross-scale training and dispatch across $\text{SF}\in\{1,10,30,100\}\text{ GB}$ (Table~\ref{tab:bigdata_multiscale_tpch} Part~A and Additional File~1, Table~S7 Part~C), rather than mixing two competing models on the same experiment. Crucially, while $\mathbf{x}_q \in \mathbb{R}^9$ encodes scale-invariant syntax topology and relative selectivity $\hat{\sigma}(q) \in (0,1]$, multi-scale awareness across $\text{SF} \in \{1, 10, 30, 100\}$ GB is achieved in Layers 2--4 by multiplying $\hat{\sigma}(q)$ with the pre-execution catalog table byte footprint $\mathcal{B}_{\text{catalog}}$ ($\hat{\mathcal{B}}_{\text{scan}}(q) = \hat{\sigma}(q)\cdot \mathcal{B}_{\text{catalog}}$) inside the analytical memory/PCIe chunk estimator and the capacity filter $\mathcal{E}_{\text{feasible}}(q)$ alongside scale-calibrated cost predictors. \subsection{Layer 2: Cross-Paradigm Analytical Cost, PCIe Crossover, and Device Energy Telemetry Formulation}
To enable apples-to-apples cost evaluation across serverless cloud, local CPU, and discrete GPU backends, Layer 2 establishes six analytical cost and hardware telemetry models:
\begin{enumerate}[leftmargin=1.5em,itemsep=3pt]
    \item \textbf{CUDA Cold-Start Decomposition and PCIe Bottleneck Fraction ($\Phi_{\text{PCIe}}$):} On discrete GPUs (NVIDIA GeForce RTX 2050, $4.0\text{ GB}$ VRAM), cold-start execution time $T_{\text{GPU\_Cold}}(q)$ is decomposed into PCIe Host-to-Device transfer time ($T_{\text{PCIe\_H2D}}$) and pure in-VRAM kernel compute time ($T_{\text{GPU\_Warm}}$):
    \begin{equation}
        T_{\text{GPU\_Cold}}(q) = \underbrace{T_{\text{PCIe\_H2D}}(q) + T_{\text{PCIe\_D2H}}(q)}_{T_{\text{PCIe}}(q)} + T_{\text{GPU\_Warm}}(q), \qquad \Phi_{\text{PCIe}}(q) = \frac{T_{\text{PCIe}}(q)}{T_{\text{GPU\_Cold}}(q)} \times 100\%
    \end{equation}
    Cold-start GPU offloading outperforms vectorized CPU execution ($T_{\text{GPU\_Cold}}(q) < T_{\text{CPU}}(q)$) if and only if the warm kernel speedup satisfies the break-even condition $\text{Speedup}_{\text{Warm}}(q) > (1 - \Phi_{\text{PCIe}}(q)/100)^{-1}$.
    \item \textbf{Effective Analytical Scan Throughput ($\Theta_{\text{eff}}$):} Normalizing unpruned columnar volume $\mathcal{B}_{\text{unopt}}(q)$ (in MB) against execution time $T_{e}(q)$ (in ms) yields effective processing throughput in $\text{GB/s}$:
    \begin{equation}
        \Theta_{\text{eff}}(q, e) = \frac{\mathcal{B}_{\text{unopt}}(q)}{1.024 \cdot \max(T_{e}(q), \epsilon_T)} \quad [\text{GB/s}]
    \end{equation}
    \item \textbf{Cloud Slot-to-Wall-Time Concurrency Proxy ($\mathcal{M}_{\text{slot}}$) and FinOps Cost Savings ($\Delta C_{\text{1M}}$):} Quantifies cumulative distributed slot compute time relative to server wall-clock time on BigQuery (serving as an effective concurrency proxy), alongside financial savings per $10^6$ queries under on-demand bytes-scanned pricing ($\alpha_{\text{TB}} = \$6.25\text{ USD/TiB}$):
    \begin{equation}
        \mathcal{M}_{\text{slot}}(q) = \frac{T_{\text{BQ\_Slot}}(q)}{T_{\text{BQ\_Wall}}(q)}, \qquad \Delta C_{\text{1M}}(q) = 10^6 \times \left( \frac{\max(\mathcal{B}_{\text{unopt}}(q), 10) - \max(\mathcal{B}_{\text{clustered}}(q), 10)}{1024^2\text{ [MiB/TiB]}} \right) \times \alpha_{\text{TB}}
    \end{equation}
    \item \textbf{Active Device Energy Telemetry ($E(q,e)$) and Three-Scope Measurement Boundary:} GPU board energy $E_{\text{GPU}}(q)$ is sampled at $50\text{--}250\text{ Hz}$ via physical NVIDIA NVML sensors (\texttt{pynvml}, $\text{CV}=1.24\%$), complemented by 1,500-run cloud RAPL/SMU/NVML telemetry and a 2,817-query ACPI DC battery-shunt audit ($\rho=0.9945$). Primary claims are restricted to directly measured \textbf{Scope~1 (GPU NVML)}, while TDP-calibrated host CPU estimates (\textbf{Scope~2}) and ACPI DC shunt envelopes (\textbf{Scope~3}) exhibit exact rank concordance ($\rho=1.0000$, \textbf{Protocol~R23}).
\end{enumerate}

\subsection{Layers 3 \& 4: Multi-Output Cost-Regression Predictor, Q-Error Metric, and Constrained Multi-Objective Dispatcher}
In Layer 3 (Fig.~\ref{fig:proposed_ast_framework}), \textbf{AST-Route} employs a Multi-Output Gradient Boosting Regressor $f_{\Theta}: \mathbb{R}^{9} \rightarrow \mathbb{R}^{M}$ to simultaneously predict log-transformed execution latency $\widehat{\ln(1 + T_e)}(\mathbf{x}_q)$, energy footprint $\hat{E}_e(\mathbf{x}_q)$, and memory consumption ($\widehat{\text{RAM}}_e, \widehat{\text{VRAM}}_e$) across the six benchmarked backends $\mathcal{E}_{\text{all}} = \mathcal{E} \cup \{\text{SQLite 3}\}$, where SQLite~3 serves as the B-tree row-store reference baseline ($0\%$ selection share under cost minimization because it is strictly dominated on $75/75$ queries) and $\mathcal{E} = \{\text{DuckDB}, \text{Polars}, \text{DataFusion}, \text{GPU}_{\text{Cold}}, \text{BigQuery}\}$ forms the five active analytical routing candidates. Predictive accuracy of the cost model is evaluated via out-of-fold log-$R^2$, Mean Absolute Percentage Error (MAPE), and the multiplicative \textbf{Q-Error} metric standard in database query optimizer research \cite{leis2015job, hilprecht2022zeroshot}:
\begin{equation}
    \text{Q-Error}(y, \hat{y}) = \max\!\left( \frac{\max(\hat{y}, \epsilon)}{\max(y, \epsilon)},\; \frac{\max(y, \epsilon)}{\max(\hat{y}, \epsilon)} \right) \ge 1.0 \quad (\epsilon = 10^{-6})
\end{equation}
In Layer 4, the dispatcher selects the optimal engine minimizing a memory-constrained, multi-objective Pareto cost function parameterized by user-configurable weights $\alpha, \beta, \gamma \in [0, 1]$ ($\alpha + \beta + \gamma = 1$, where $\alpha$ weights normalized latency $\hat{T}_e/T_{\text{med}}$, $\beta$ weights normalized energy $\hat{E}_e/E_{\text{med}}$, and $\gamma$ weights normalized marginal cloud scan charge $\hat{C}_e/C_{\text{ref}}$) subject to hardware memory capacity budgets ($\widehat{\text{RAM}}_e(\mathbf{x}_q) \le M_{\text{host\_max}}$ and $\widehat{\text{VRAM}}_e(\mathbf{x}_q) \le M_{\text{gpu\_max}}$). Let $e_T^*(q) = \operatorname*{arg\,min}_{e \in \mathcal{E}} T_e(q)$, $e_E^*(q) = \operatorname*{arg\,min}_{e \in \mathcal{E}} E_e(q)$, and $e_C^*(q) = \operatorname*{arg\,min}_{e \in \mathcal{E}} C_e(q)$ denote the ground-truth per-dimension Oracles; we evaluate multi-objective routing across Latency Regret ($\mathcal{R}_T \equiv \mathcal{R}_{\text{regret}}$), Energy Regret ($\mathcal{R}_E$), Cloud FinOps Cost Regret ($\mathcal{R}_C$), 3D Normalized Pareto Hypervolume ($\text{HV}_{\mathbf{r}}(\Pi)$ relative to nadir $\mathbf{r}=(1,1,1)$ via 3D Lebesgue measure $\lambda_3$), and Dominated Solution Ratio ($\text{DSR}(\Pi)$):
\vspace{-3pt}
\begin{equation}
\begin{aligned}
    \hat{e}_{\alpha,\beta,\gamma}(q) &= \operatorname*{arg\,min}_{e \in \mathcal{E}_{\text{feasible}}(q)} \left[ \alpha \frac{\hat{T}_e(\mathbf{x}_q)}{T_{\text{med}}(q)} + \beta \frac{\hat{E}_e(\mathbf{x}_q)}{E_{\text{med}}(q)} + \gamma \frac{\hat{C}_e(\mathbf{x}_q)}{C_{\text{ref}}(q)} \right], \;\;
    \text{HV}_{\mathbf{r}}(\Pi) = \lambda_3\!\left(\bigcup_{\pi\in\Pi}\big[\tilde{\mathbf{f}}(\pi),\mathbf{r}\big]\right), \;\;
    \text{DSR}(\Pi) = \frac{100\%}{|\Pi|}\sum_{\pi\in\Pi}\mathbb{I}\!\left(\exists\pi'\!\in\!\Pi:\, \mathbf{f}(\pi') \!\prec\! \mathbf{f}(\pi)\right), \\
    \mathcal{R}_{T}(q) &= \frac{T_{\hat{e}}(q) - T_{e_T^*}(q)}{T_{e_T^*}(q)}\!\times\! 100\%, \;\; \Delta T_{\text{abs}}(q) = T_{\hat{e}}(q) - T_{e_T^*}(q), \;\;
    \mathcal{R}_{E}(q) = \frac{E_{\hat{e}}(q) - E_{e_E^*}(q)}{E_{e_E^*}(q)}\!\times\! 100\%, \;\;
    \mathcal{R}_{C}(q) = \frac{C_{\hat{e}}(q) - C_{e_C^*}(q)}{\max(C_{\text{BQ}}(q),\epsilon)}\!\times\! 100\%
\end{aligned}
\end{equation}
\vspace{-2pt}
where $\tilde{\mathbf{f}}(\pi) = (\tilde{T}_\pi, \tilde{E}_\pi, \tilde{C}_\pi) \in [0,1]^3$ maps each policy's mean latency, energy, and cloud scan cost into unit hypervolume coordinates via $\tilde{m}_\pi = \min\!\big(1, (m_\pi - m_{\min})/\max(m_{\text{nadir}} - m_{\min}, \epsilon)\big)$ relative to the oracle utopia point $\mathbf{f}_{\min}$ and static-engine nadir $\mathbf{r}=(1,1,1)$, $\mathcal{R}_C(q)$ is normalized by $\max(C_{\text{BQ}}(q), \epsilon)$ to prevent division by zero when $C_{e_C^*}(q) = \$0.00$ on local engines, and we report both relative percentage regret $\mathcal{R}_{T}(q)$ and absolute millisecond regret $\Delta T_{\text{abs}}(q)$ alongside Expected Shortfall $\text{CVaR}_{\alpha_{\text{tail}}}$ over the worst $\alpha_{\text{tail}}\in\{10\%,20\%\}$ tail queries. Alongside \textbf{Policy P1: Speed-First ($\alpha=1,\beta=0,\gamma=0$)}, we evaluate canonical multi-objective Policies \textbf{P2: Energy-First $(0.1,0.8,0.1)$} ($\mathcal{R}_E=4.82\%$, $0.812\text{ J/q}$, $-41.2\%$ energy vs.\ P1 and $-74.4\%$ vs.\ Polars), \textbf{P3: Cost-First FinOps $(0.2,0.1,0.7)$} ($\mathcal{R}_C=0.0\%$, $\$0.00/1\text{M}$ cloud spend saving $\$507.06/1\text{M}$ at $\text{SF}=100\text{ GB}$), and \textbf{P4: Balanced Pareto Knee $(0.5,0.3,0.2)$} ($55.48\text{ ms}$ net [$+0.56\text{ ms}$ vs.\ P1], $1.045\text{ J/q}$ [$-24.3\%$], $\mathcal{R}_E=18.2\%$) across both a canonical 15-weight simplex grid and a dense \textbf{500-point randomized Dirichlet simplex sample plus 100-point uniform lattice} $(\alpha,\beta,\gamma)\in\Delta^2$ (Table~\ref{tab:v9_mo_energy_ood_repro_synthesis} Part~A and Protocol~\textbf{R11}), confirming that AST-Route is \textbf{Pareto-efficient among the evaluated policy configurations} with 3D Hypervolume $\text{HV}\in[0.8965,0.9210]$ (500-point mean $\text{HV}=0.9184\pm 0.0042$) at $\text{SF}=1\text{ GB}$ and $\text{HV}\in[0.9045,0.9340]$ at $\text{SF}=100\text{ GB}$ (vs.\ $0.5180$ static Polars), a $\mathbf{0.0\%}$ \textbf{Dominated Solution Ratio ($\text{DSR}=0/15$ grid and $0/500$ Dirichlet points dominated vs.\ $100.0\%$ on static CPU/Cloud baselines)}, and $\mathbf{96.00\%\text{--}98.67\%}$ engine-selection stability under $\pm 0.05$ weight perturbations. To decouple query syntax from deployment hardware, each physical node is characterized by a five-dimensional \textbf{Hardware Descriptor Vector} $\mathbf{h}_{\text{hw}} = [M_{\text{host\_max}},\, M_{\text{gpu\_max}},\, B_{\text{PCIe}},\, N_{\text{CPU}},\, B_{\text{MEM}}]^{\top} \in \mathbb{R}^{5}$ encoding host DBMS RAM cap ($\text{GB}$), device VRAM cap ($\text{GB}$), sustained pinned PCIe DMA bandwidth ($\text{GB/s}$), logical CPU thread count, and host DRAM bandwidth ($\text{GB/s}$): specifically, Node~1 (\texttt{G1}: $\mathbf{h}_{\text{hw}}^{(1)} = [9.0, 4.0, 5.69, 8, 25.6]^{\top}$), Node~2 ($\mathbf{h}_{\text{hw}}^{(2)} = [9.0, 0.0, 0.0, 22, 42.7]^{\top}$), Node~3 Apple M1 \texttt{ARM64} ($\mathbf{h}_{\text{hw}}^{(3)} = [8.0, 0.0, 0.0, 8, 68.3]^{\top}$), and Node~4 Cloud-Hosted Server NVIDIA Tesla~T4 (\texttt{G2}: $\mathbf{h}_{\text{hw}}^{(4)} = [12.7, 15.0, 9.43, 2, 320.0]^{\top}$). Here $\mathcal{E}_{\text{feasible}}(q, \mathbf{h}_{\text{hw}}) = \{e \in \mathcal{E} \mid \widehat{\text{RAM}}_e(\mathbf{x}_q) \le M_{\text{host\_max}} \land \widehat{\text{VRAM}}_e(\mathbf{x}_q) \le M_{\text{gpu\_max}}\}$ prunes any candidate engine whose predicted memory footprint violates hardware capacity ceilings prior to objective scoring (automatically disabling GPU dispatch when $M_{\text{gpu\_max}}=0$), while few-shot cross-node transfer ($m \in \{1,3,5,10,15\}$ calibration queries in Section~\ref{sec:v852_reviewer_audit}) adjusts log-latency predictions via a per-engine hardware scaling offset $\hat{z}_e(\mathbf{x}_q, \mathbf{h}_{\text{hw}}) = \hat{z}_e^{\text{src}}(\mathbf{x}_q) + \hat{\delta}_e(\mathbf{h}_{\text{hw}})$, and each objective term is normalized by its cross-engine reference scale ($T_{\text{med}}(q)$, $E_{\text{med}}(q)$, and $C_{\text{ref}}(q) = \max(C_{\text{BQ}}(q), \epsilon)$). Per $10^6$ queries, we separate incremental \emph{On-Demand Cloud Query Scan Charge} $\hat{C}_e(\mathbf{x}_q)$ ($\$0.00$ local vs.\ $(\hat{\mathcal{B}}_{\text{clustered}}(\mathbf{x}_q)/2^{40})\times\$6.25/\text{TiB}$ on BigQuery), active device energy $\hat{E}_e(\mathbf{x}_q)$ ($\$0.02\text{--}\$0.21/1\text{M}$ at $\$0.12/\text{kWh}$), and sunk local workstation amortization ($\$0.58\text{--}\$1.94/1\text{M}$ at $\$0.038/\text{hr}$).

Specifically, predicted log-latencies $\hat{z}_e(\mathbf{x}_q) = \widehat{\ln(1+T_e)}(\mathbf{x}_q)$ are mapped back to the millisecond domain via $\hat{T}_e(\mathbf{x}_q) = \max(\exp(\hat{z}_e(\mathbf{x}_q)) - 1, \epsilon)$. For each outer cross-validation fold $k$, AST-Route computes the empirical $(1-\alpha_{\text{conf}})=90\%$ split/cross-conformal quantile $\hat{q}_{0.90,e}^{(-k)} = \text{Quantile}_{0.90}\big(\{|\ln(1+T_e(q_i)) - \hat{z}_e^{(-k)}(\mathbf{x}_{q_i})|\}_{q_i \in \mathcal{D}_{\text{train}}^{(-k)}}\big)$ with clamped finite-sample correction $q_{\text{level}}(n_{\text{cal}},\alpha_{\text{conf}}) = \min\!\big(1.0,\, \lceil(n_{\text{cal}}+1)(1-\alpha_{\text{conf}})\rceil/n_{\text{cal}}\big)$ ensuring valid quantile indexing even on small strata (alongside a complexity-stratified Mondrian conformal variant scaled by tier dispersion $\hat{\sigma}_{\text{tier}}(\text{CSCI}(q))$ to preserve conditional coverage across heterogeneous operator tiers, outperforming uncalibrated pinball-loss quantile regression \texttt{GBR-Quantile} in Table~\ref{tab:v9_reviewer_reanalysis_matrix} Part~D) strictly inside the training fold, yielding the calibrated prediction interval:
\begin{equation}\label{eq:conformal_interval}
[\hat{L}_{0.90,e}(q),\, \hat{U}_{0.90,e}(q)] = \Big[\max\!\big(\exp(\hat{z}_e(\mathbf{x}_q) - \hat{q}_{0.90,e}^{(-k)}) - 1,\, \epsilon\big),\; \exp(\hat{z}_e(\mathbf{x}_q) + \hat{q}_{0.90,e}^{(-k)}) - 1\Big]
\end{equation}
Using complexity-weighted Mondrian conformal quantiles $\hat{q}_{1-\alpha}(e, L_m)$ calibrated out-of-fold across tiers $L_1\text{--}L_5$ ($90.93\%$ empirical coverage, $\text{ECE}=0.67\%$, $\text{AURC}=28.14\%$), Algorithm~1 enforces four pre-execution safety guards: \textbf{Rule~U1} (parallel $8\%$ Nested-CV and $12\%$ Default PCIe crossover margin guard), \textbf{Rule~U2} ($90\%$ conformal cloud upper-bound gate), \textbf{Rule~U3} (unanchored string guard), and \textbf{Rule~U4} (hard VRAM/DRAM capacity pruning $\mathcal{E}_{\text{feasible}}(q)$ + Mahalanobis OOD gate $\text{AUROC}=0.9642$).

To rigorously prevent data leakage across query variations sharing the same template structure, we evaluate \textbf{AST-Route} under three complementary validation protocols: (i) \textbf{25-fold Leave-One-Seed-Out cross-validation (LOSO-CV)} across all 25 disjoint seed groups ($N=75$ queries), (ii) a \textbf{Strict Unseen Seed Holdout Split}, where the framework is trained exclusively on 20 development seeds (\texttt{S1}--\texttt{S4} across L1--L5, $N_{\text{dev}}=60$ queries) and evaluated once on 5 completely locked unseen test seeds (\texttt{L1\_\allowbreak{}S5, L2\_\allowbreak{}S5, L3\_\allowbreak{}S5, L4\_\allowbreak{}S5, L5\_\allowbreak{}S5}, $N_{\text{unseen}}=15$ queries), and (iii) \textbf{Strict Nested 22-fold Leave-One-Query-Out cross-validation (Nested LOO-CV)} on the 22 official standard TPC-H benchmark queries (\textbf{Q1--Q22}) \cite{tpc2022tpch}, where feature calibration weights are tuned strictly inside the 21-query inner training loop without touching the held-out test query. We benchmark \textbf{AST-Route} ($\mathcal{R}_{\text{RF-9D}}$ and $\mathcal{R}_{\text{GBR-9D}}$) against four baseline policies: \textbf{(1) Always DuckDB}, \textbf{(2) Always GPU (Cold-Start)}, \textbf{(3) Always BigQuery (Cloud OLAP)}, and \textbf{(4) Rule-Based Routing} across Execution Time ($T_{\pi}$), Routing Accuracy ($\text{Acc}_{\text{top1}}$, $\text{Acc}_{\text{top2}}$, $\le 10\%$ near-optimal hit rate, and zero-regret hit rate), Resource Cost, and Normalized Performance Regret ($\mathcal{R}_{\text{regret}}$, including Mean, Median P50, P90, and P95 Tail Regret).

    \begin{equation}\label{eq:v9_sql_vs_tensor_attribution}
        \Delta \bar{T}_{\text{total}} = \bar{T}_{e^*_{\text{CPU}}} - \bar{T}_{\pi(\mathcal{E}_{\text{All-6}})} = \underbrace{\big(\bar{T}_{e^*_{\text{CPU}}} - \bar{T}_{\pi(\mathcal{E}_{\text{SQL-5}})}\big)}_{\Delta_{\text{SQL-Only}} = 13.35\text{ ms}\ (48.5\%)} + \underbrace{\big(\bar{T}_{\pi(\mathcal{E}_{\text{SQL-5}})} - \bar{T}_{\pi(\mathcal{E}_{\text{All-6}})}\big)}_{\Delta_{\text{Tensor-Offload}} = 14.20\text{ ms}\ (51.5\%)} = 27.55\text{ ms}
    \end{equation}
    confirming that $48.5\%$ of the latency reduction over the best single CPU engine ($2.77\times$ P95 tail-regret reduction: $118.50\% \rightarrow 42.80\%$ vs.\ $\mathcal{E}_{\text{Local-CPU-3}}$ oracle [$58.42\text{ ms}$]; $358.40\% \rightarrow 168.50\%$ vs.\ $\mathcal{E}_{\text{All-6}}$ oracle [$42.64\text{ ms}$]) is achieved purely by routing among standard SQL engines, while the minimalist 2-engine subset $\mathcal{E}_{\text{Min-2}}=\{\text{Polars},\text{GPU}\}$ ($55.28\text{ ms}$) captures $\mathbf{98.7\%}$ of the full 6-engine gain.
\end{enumerate}

Even under conservative Level~3 accounting ($+4.15\text{ ms}$ SQL-to-tensor lowering charged to GPU), in-memory GPU execution ($61.11\text{ ms}$) outperforms Polars ($82.47\text{ ms}$) by $1.35\times$ and DuckDB ($183.74\text{ ms}$) by $3.01\times$.
\end{itemize}

\subsection{Head-to-Head Evaluation of AST-Route Against Four Routing Baselines (25-Seed LOSO-CV)}
Table~\ref{tab:routing_evaluation} and Fig.~\ref{fig:ast_query_router} present the comparative evaluation of our Proposed \textbf{AST-Route} Framework (Fig.~\ref{fig:proposed_ast_framework}) against static, heuristic, and guarded/unguarded linear and shallow-tree baselines under 25-seed Leave-One-Seed-Out cross-validation (guaranteeing zero data leakage across variations V1--V3):
\begin{enumerate}[leftmargin=1.5em,itemsep=1pt]
    \item \textbf{Static Single-Engine, Simple Heuristic (\texttt{H1--H5}), and Stronger GPU Baselines (\texttt{Pinned-Overlap FP64/FP32}, \texttt{Resident-VRAM}, \texttt{RAPIDS cuDF / cudf-polars}):} Static engines exhibit pronounced regime trade-offs: \textbf{Always DuckDB} ($183.74\text{ ms}$, $928.32\%$ P95 regret), \textbf{Always Polars} ($82.47\text{ ms}$, $358.40\%$ P95 regret), \textbf{Always GPU Cold FP64} ($56.96\text{ ms}$, $257.31\%$ P95 regret due to PCIe H2D stalls on L1/V1), and \textbf{Always BigQuery} ($745.39\text{ ms}$, $\$1{,}267.66/1\text{M}$ queries at $\text{SF}=1\text{ GB}$). Five domain heuristics (Table~\ref{tab:routing_evaluation}: static byte rule \textbf{H1} [$353.89\%$ P95 regret, $p_{\text{Webb}}=0.0084$], CV-tuned byte rule \textbf{H2} [$307.55\%$ P95, $p_{\text{Webb}}=0.0112$], operator rule \textbf{H3} [$413.69\%$ P95, $p_{\text{Webb}}=0.0062$], 2-condition rule \textbf{H4} [$353.89\%$ P95, $p_{\text{Webb}}=0.0148$], and depth-1 stump \textbf{H5} [$325.58\%$ P95, $p_{\text{Webb}}=0.0124$]) suffer $2.60\times\text{--}3.63\times$ higher P95 regret than AST-Route because 1D thresholds cannot separate the oblique operator$\times$selectivity PCIe boundary.     \item \textbf{Locked Primary Nested-CV Guard ($\hat{\tau}_{\text{guard}}^{(-k)}=8\%$), Global Holm--Bonferroni Control, and Baseline Attribution:} To avoid post-hoc threshold selection, the inner-fold modal \textbf{Nested-CV Guard ($\hat{\tau}_{\text{guard}}^{(-k)}=8\%$, Row~5b)} serves as our sole pre-specified primary router, achieving $51.22\text{ ms}$ exec ($\mathbf{55.37\text{ ms}}$ net), $\mathbf{118.40\%}$ P95 regret, $\mathbf{56.00\%}$ Exact Top-1 ($\mathbf{76.00\%}$ Top-2), and passing all three primary superiority/non-inferiority tests under global Holm--Bonferroni multiplicity control ($M=4$ tests): P95 reduction vs.\ Always GPU ($2.17\times$ cut, $p_{\text{raw}}=0.0068, p_{\text{Holm}}=0.0136, p_{\text{tpl}}=0.0074, p_{\text{perm,exact}}=0.0078$), mean speedup vs.\ Polars ($1.49\times$, $p_{\text{raw}}=0.0028, p_{\text{Holm}}=0.0084$; $p_{\text{Holm,seed}}=0.0171, p_{\text{Holm,query}}=0.0011$), and $+10\%$ relative mean non-inferiority vs.\ Always GPU ($p_{\text{raw}}=0.0012, p_{\text{Holm}}=0.0048$; exploratory overhead-anchored $\pm 5.0\text{ ms}$ TOST $p_{\text{TOST}}=0.0442$). \subsection{Internal Framework Validation: Feature Ablation, Multi-Objective Pareto Trade-off, Noise Robustness, and Overhead Breakdown}
To rigorously validate the internal mechanisms of \textbf{AST-Route}, Table~\ref{tab:jbd_ablation_t9} (and Additional File~1, Table~S11) and Additional File~1 (Fig.~S6) report six additional verification experiments under 25-seed LOSO-CV:
\begin{enumerate}[leftmargin=1.5em,itemsep=1pt]
    \item \textbf{Three-Way Stepwise Decomposition (\texttt{Guard Only} $\rightarrow$ \texttt{+Conformal} $\rightarrow$ \texttt{+CSCI}), Exact TreeSHAP Attribution, and Failure Taxonomy (Table~\ref{tab:jbd_ablation_t9} Exp~A \& Exp~D):} To separate the effect of the threshold guard from conformal calibration and $\text{CSCI}(q)$, Table~\ref{tab:jbd_ablation_t9} (Exp~D) decomposes routing progression across four stepwise stages: \textbf{(Stage~0) Unguarded 8D Raw-AST + $\hat{\sigma}$} ($53.84\text{ ms}$ net, $46.85\%$ mean regret, $214.60\%$ in-domain P95 regret, $248.50\%$ drift P95 regret, $6.84$ splits/tree, $58.59\%$ zero-shot TPC-DS Top-1); \textbf{(Stage~1) + Threshold Margin Guard Only ($\tau_{\text{guard}}=8\%$ on 8D)} cuts in-domain P95 regret by $\mathbf{-78.20\text{ pp}}$ to $\mathbf{136.40\%}$ (95\% CI $[-142.50,-24.80]\text{ pp}, p_{\text{Webb}}=0.0082$), establishing that $\mathbf{81.3\%}$ of the in-domain P95 reduction is achieved by the margin threshold guard itself; \textbf{(Stage~2) + Tier-Stratified $90\%$ Mondrian Conformal Guard} yields a further $-11.60\text{ pp}$ in-domain P95 shift ($124.80\%$), while cutting $\text{CVaR}_{10\%}$ by $\mathbf{-31.40\text{ pp}}$ and reducing P95 regret under \textbf{selectivity/distribution drift and cloud spill gating} by $\mathbf{-48.60\text{ pp}}$ ($182.40\%\rightarrow \mathbf{133.80\%}$, 95\% CI $[-76.20,-21.40]\text{ pp}, p=0.0018$); and \textbf{(Stage~3) + Oblique $\text{CSCI}(q)$ Projection (Full 9D AST-Route)} lowers in-domain mean regret by $\mathbf{-5.40\text{ pp}}$ ($41.20\%\rightarrow \mathbf{35.80\%}$, 95\% CI $[-9.80,-1.60]\text{ pp}, p=0.0038$), reaches $\mathbf{118.40\%}$ P95 regret ($114.11\%$ at $12\%$), prunes active GBDT splits by $\mathbf{-28.22\%}$ ($6.84\rightarrow 4.91$ splits/tree across $25/25$ seeds, outperforming in-fold $\text{PCA}_1$ [$57.48\text{ ms}, p=0.0124$], $\text{PCA}_{1,2}$ [$57.19\text{ ms}, p=0.0156$], and Random Oblique [$57.85\text{ ms}, p=0.0068$]), and lifts zero-shot Top-1 accuracy on Official TPC-DS ($58.59\%\rightarrow\mathbf{64.65\%}$) and 80 public SQL/trace queries ($83.75\%\rightarrow\mathbf{91.25\%}$). Mathematically, because $\text{CSCI}(q)=\mathbf{w}^{\top}\mathbf{z}\in\text{span}(\{D,J,S,W,U,C\})$, conditional variance within exact $(D..C)$ strata is $\operatorname{Var}(\text{CSCI}\mid D..C)=0.0000$ ($I(\text{CSCI};Y\mid D..C)=0\text{ bits}$), whereas \textbf{Grouped Atomic-Block Permutation} within $(V_{\text{scan}},\sigma_{\text{sel}})$ strata degrades regret by $\mathbf{+33.44\text{ pp}}$ ($p=0.0002$). Across all $N=75$ queries, \textbf{Exact TreeSHAP Attribution} (\texttt{results/v12\_r33\_misrouted\_failure\_taxonomy\_treeshap\_pool\_ablation.csv}) shows that routing decisions are governed by $\hat{\sigma}(q)$ ($\mathbf{34.2\%}$ of $|\text{SHAP}|$), $\text{CSCI}(q)$ ($\mathbf{24.8\%}$), $J(q)$ ($\mathbf{14.6\%}$), $W(q)$ ($\mathbf{10.4\%}$), $U(q)$ ($\mathbf{7.8\%}$), and $D,N,S,C$ ($\mathbf{8.2\%}$). Categorizing all $33/75$ ($44.0\%$) non-Top-1 dispatches under the $8\%$ guard reveals three distinct regimes: \textbf{(F1) Sub-$5\text{ ms}$ Near-Tie Boundary Noise} ($21/33 = \mathbf{63.6\%}$ of misroutes, where $|\Delta T_{\text{abs}}|\le 5.0\text{ ms}$ and mean penalty is only $+1.84\text{ ms}$), \textbf{(F2) Intentional Rule~U1 Safety Abstentions} ($7/33 = \mathbf{21.2\%}$, where GPU was faster by $4.2\text{--}9.8\text{ ms}$ but predicted margin was $<8\%$, paying $+6.42\text{ ms}$ as insurance to prevent $14/75$ severe PCIe stalls), and \textbf{(F3) Zone-Map Join-Selectivity Misestimation} ($5/33 = \mathbf{15.2\%}$, $+18.65\text{ ms}$ on skewed multi-joins, mitigated via our $10.18\text{ KB}$ 12D join sketch).
    \item \textbf{Constrained 3D Pareto Frontier (Exp~B), Selectivity Noise Robustness (Exp~C), and 5-Metric Operational Complexity (Exp~E):} Across $(\alpha,\beta,\gamma)\in\Delta^2$, Policy~B2--B5 compress device energy by up to $-45.8\%$, B6 enforces $M_{\text{gpu\_max}}\le 1.28\text{ GB}$ with $0\%$ OOM, and at $\text{SF}=100\text{ GB}$, Cloud-Elastic B7 achieves $1{,}142.8\text{ ms}$ ($\$507.06/1\text{M}$) while FinOps B8 sustains $1{,}326.9\text{ ms}$ at $\$0.00$ cloud cost. Under $\pm 10\%\text{--}50\%$ Monte Carlo selectivity noise and $50\%$ metadata masking (Exp~C), AST-Route sustains $68.42\text{--}80.98\text{ ms}$ (faster than all static CPUs). Total pre-execution router overhead (Exp~E) is $\mathbf{4.145\text{ ms}}$ in Cold-SQL Regime~O1 ($3.476\text{ ms}$ \texttt{SQLGlot} parse $+ 0.172\text{ ms}$ zone-map $+ 0.497\text{ ms}$ GBDT inference), $\mathbf{0.669\text{ ms}}$ in AST-cached Regime~O2, and $\mathbf{0.082\text{ ms}}$ in 1D threshold-cached Regime~O3 ($1.42\text{ MB}$ resident RAM, $284\text{ KB}$ model, $0.38\text{ s}$ training).

\subsubsection{Seed-Level ($K=25$) Statistical Inference, TOST Margin Sensitivity ($\pm 2\text{--}8\text{ ms}$), $\text{CVaR}_{10\%}/\text{CVaR}_{20\%}$ Tail Regret, Nadeau--Bengio CV Correction, and Standalone CPU-Only Routing}
\label{sec:seed_level_statistical_inference}
Repeating non-parametric tests strictly on independent seed means ($K=25$ clusters, $N=75$ queries, $375$ timed trials at $\text{SF}=1\text{ GB}$; full bootstrap CIs and baseline matrix in Additional File~1, Tables~S6--S7 and Fig.~S6) confirms cross-engine stratification ($\chi^2_F(5)=93.43, p < 0.001$, Kendall's $W=0.7475$) and establishes our two primary evaluation endpoints via 10,000-iteration paired bootstrap 95\% confidence intervals ($\Delta = \text{AST-Route} - \text{Baseline}$), formal Two One-Sided Tests (TOST) equivalence bounds across $\Delta_{\text{eq}}\in\{\pm 2, \pm 3, \pm 5, \pm 6, \pm 8\}\text{ ms}$ (Fig.~\ref{fig:job_12d_ablation_fig}c), \textbf{Conditional Value-at-Risk ($\text{CVaR}_{\alpha_{\text{tail}}}$)}, and \textbf{Nadeau--Bengio (2003) CV-overlap variance-corrected paired $t$-tests}:
\vspace{-3pt}
\begin{equation}\label{eq:nadeau_bengio_t}
    t_{L} = \frac{\bar{d} + \Delta_{\text{eq}}}{s_d / \sqrt{K}}, \;\; t_{U} = \frac{\bar{d} - \Delta_{\text{eq}}}{s_d / \sqrt{K}}, \;\; p_{\text{TOST}} = \max\!\big(1 - \Phi_{t,K-1}(t_L),\, \Phi_{t,K-1}(t_U)\big), \;\; t_{\text{NB}} = \frac{\bar{d}}{\sqrt{\big(\frac{1}{K} + \frac{n_{\text{test}}}{n_{\text{train}}}\big) s_d^2}}, \;\; \text{CVaR}_{\alpha_{\text{tail}}} = \frac{1}{k_{\alpha}}\sum_{i=1}^{k_{\alpha}} \mathcal{R}_{T,(N-i+1)}
\end{equation}
\vspace{-2pt}
where $\bar{d}$ and $s_d^2$ denote the sample mean and variance of seed-cluster differences $d_k$ ($K=25,\; n_{\text{test}}=3,\; n_{\text{train}}=72$, variance inflation factor $1.4289$). Full statistical and systems audit matrices are archived in Additional File~1 (Tables~S16--S33); three core findings govern deployment (Table~\ref{tab:v11_r23_r22_energy_and_dynamic_sla}):
\begin{enumerate}[leftmargin=1.5em,itemsep=1pt]
    \item \textbf{Expanded $G_{\text{total}}=42$ Template-Cluster Linear Mixed-Effects (LME) Model, Global Holm Control, and Engine-Pool Ablation:} To overcome small-sample limits on the 10-cluster core benchmark ($G_{\text{core}}=10$, where Webb 6-point wild cluster bootstrap and exact $2^{10}=1{,}024$ sign-flip permutation confirm P95 tail reductions vs.\ Always GPU at $p_{\text{Webb}}=0.0068/0.0054$ and RMM-pooled \texttt{cudf-polars C3} at $p_{\text{Webb}}=0.0042$, while Unguarded Ridge is borderline at $p_{\text{Webb}}=0.0464, p_{\text{perm,exact}}=0.0488$), we pool out-of-fold / held-out evaluations across $\mathbf{G_{\text{total}}=42}$ \textbf{independent template families ($N=312$ queries across TPC-H [$10$], Official TPC-DS [$15$], IMDB JOB [$7$], ClickBench [$5$], SSB [$4$], and Public Trace [$1$])}. Fitting a Restricted Maximum Likelihood (REML) \textbf{Hierarchical Linear Mixed-Effects Model} ($\text{Regret}_{ij} = \beta_0 + \beta_{\text{policy}}\mathbb{I}(\text{AST-Route}) + u_{0,g(i)} + \epsilon_{ij}$) confirms a highly significant cross-cluster regret reduction of $\mathbf{\hat{\beta}_{\text{policy}}=-62.06\text{ pp}}$ ($\text{SE}=1.08\text{ pp}$, 95\% CI $[-64.18,-59.94]\text{ pp}, z=-57.37, p<10^{-15}$). Engine-pool ablation confirms that a \textbf{Minimalist 2-Engine Subset ($\mathcal{E}_{\text{Min-2}}=\{\text{Polars},\text{GPU}\}$: $55.28\text{ ms}$)} captures $\mathbf{98.7\%}$ of the 6-engine latency gain at $\text{SF}=1\text{ GB}$ ($\mathcal{E}_{\text{Prod-3}}=\{\text{DuckDB},\text{Polars},\text{GPU}\}$: $55.07\text{ ms}$, $99.5\%$; Pure-SQL $\mathcal{E}_{\text{SQL-5}}$: $69.12\text{ ms}$, $74.67\%$ Top-1), while DuckDB decorrelates TPC-H Q16--Q22 / TPC-DS subqueries and BigQuery is required only at $\text{SF}=100\text{ GB}$ when local CPUs spill to NVMe.
    \item \textbf{Multi-Objective Pareto Optimality and Query-Level ($N=75$) Hardware Energy Boundary:} Across a 10,000-point Dirichlet simplex, NSGA-II, and MOBO (qEHVI) (Additional File~1, Table~S27), Dominated Solution Ratio is $\text{DSR}=0.00\%$ and Policy~P4 $(0.5,0.3,0.2)$ captures $99.96\%$ ($\text{HV}=0.9210$ vs.\ $0.9214$) of the continuous Pareto optimum. In Table~\ref{tab:v11_r23_r22_energy_and_dynamic_sla} (Part~A), primary energy claims rely strictly on \textbf{Scope~1 Direct Physical NVML/RAPL Hardware Sensors} ($0.644\text{ J/q}$ Node~1 GPU, $0.875\text{ J/q}$ Node~4 Tesla~T4), whereas TDP-calibrated composite host+GPU estimates (\textbf{Scope~2}: $1.658\text{ J/q}$ P2 vs.\ $2.273\text{ J/q}$ P1, $-27.1\%$) and mainboard ACPI DC battery-shunt envelopes (\textbf{Scope~3}: $1.892\text{ vs.\ }2.584\text{ J/q}$) are reported as secondary system approximations; across all $\mathbf{N=75}$ \textbf{individual queries ($\text{df}=73$)}, query-level Spearman rank correlation between Scope~1 NVML sensor energy and Scope~3 DC shunt telemetry is $\mathbf{\rho_{N=75}=0.9684}$ ($t=33.18, p=1.4\times 10^{-45}$, 95\% CI $[0.949,0.981]$).
    \item \textbf{Concurrency Contention ($C=1\text{--}64$), Dynamic Drift/Burst SLA Stress, and 4-Node Calibration:} Dual-path CPU+GPU dispatch reaches $154.44\text{ QPS}$ at $C=32$ ($2.14\times$ vs.\ CPU), and across 5 dynamic drift/burst phases (Table~\ref{tab:v11_r23_r22_energy_and_dynamic_sla} Part~B), PSI/conformal/U4 gates maintain $0.00\%$ OOM and $0.00\%\text{--}2.00\%$ SLA violations (vs.\ $14.0\%$ OOM unguarded), while $m=5$ affine canary calibration ($0.19\text{--}0.24\text{ s}$, Part~C) recovers $86.8\%\text{--}100.0\%$ of full target-node retraining gains across Nodes~1--4.
\end{enumerate}

\section{Mechanistic Systems Synthesis, Deployment Guidelines, and Threats to Validity}
\par\noindent\textbf{Five Physical Systems Mechanisms \& Four Validity Dimensions.} Across all $400$ benchmark, $70$ enterprise stress, and $50$ public real-world SQL queries, five physical mechanisms govern routing: \textbf{(M1) PCIe H2D Transfer Bottleneck in Low-CSCI Scans (L1)} ($\Phi_{\text{PCIe}}=55.5\%\text{--}56.0\%$ at $5.69\text{ GB/s}$ misses the $2.25\times$ warm break-even, favoring Arrow SIMD CPU); \textbf{(M2) SIMT Radix/Prefix Amortization in High-CSCI Joins, Windows, \& Unnests (L2--L5)} ($2.09\times\text{--}8.52\times$ cold GPU speedup); \textbf{(M3) Morsel-Driven Subquery Decorrelation in DuckDB (TPC-H Q16--Q22 \& Official TPC-DS)} ($22.82\text{ ms}$ on Q1--Q22); \textbf{(M4) Zone-Map Blindness on Infix Strings vs.\ $10.18\text{ KB}$ 12D Sketches (JOB)} ($21.21\%\rightarrow 69.70\%$ Top-1, $4.54\text{ ms}$); and \textbf{(M5) Host DRAM Spill Cliffs vs.\ Chunked GPU Streaming \& Cloud Slots ($\text{SF}=100\text{ GB}$)} ($3{,}302\text{ MB}$ NVMe spill vs.\ $0\text{ MB}$ GPU spill and BigQuery elasticity). Threats to validity are bounded across four dimensions: (1) \emph{Internal Validity}: verified via Pure Native-SQL routing ($\mathcal{E}_{\text{SQL-Only}}$), common cold Parquet boundaries, and independent third-party GPUs (\texttt{CuPy v14.2.0}, RMM-pooled \texttt{NVIDIA RAPIDS cudf-polars 26.10.2}, and Node~4 Cloud-Hosted Server NVIDIA Tesla~T4 $15.0\text{ GB}$ VRAM); (2) \emph{Operator-Tier Alignment}: pre-execution overhead is separated across Cold-SQL O1 ($4.15\text{ ms}$), Warm AST-Cache O2 ($0.67\text{ ms}$), and 1D Gate O3 ($0.08\text{ ms}$), and primary energy claims are restricted to Scope~1 hardware NVML/RAPL sensors (\textbf{Protocol~R23}, $\rho=1.0000$); (3) \emph{External Validity}: separated across our 4-category 400-query benchmark taxonomy ($155$ untouched Category~IV queries), $70$ author-constructed enterprise stress templates (\textbf{Protocols~R17+R20}), and $50$ third-party public real-world SQL queries (\textbf{Protocol~R27b}: SDSS DR16 + NYC TLC); and (4) \emph{Statistical Conclusion Validity}: parallel $8\%$ Nested-CV ($p_{\text{TOST}}=0.0442$) and $12\%$ Default ($p_{\text{non-inf}}=0.00067$) guards are verified via Nadeau--Bengio CV correction ($p_{\text{NB}}=0.0118$) and $G_{\text{core}}=10$ Webb 6-point / exact $2^{10}$ permutation tests (\textbf{Protocol~R26}), where we transparently report borderline P95 significance vs.\ Unguarded Ridge ($p_{\text{Webb}}=0.0464, p_{\text{perm,exact}}=0.0488$) and P95 parity with Guarded Ridge ($p_{\text{Webb}}=0.3840$).

similarly, on homogeneous workloads or uncontended server GPUs when only mean latency matters (\textbf{R2}), static execution suffices and AST-Route serves purely as an optional tail/OOM guard; (ii) \textbf{When AST-Route Delivers Peak Value (Regimes~R3 \& R4)}: on mixed OLAP workloads over VRAM/PCIe-constrained GPUs (\textbf{R3}, $25\text{--}250\text{ ms}$, cutting P95 regret by $2.17\times\text{--}2.77\times$ vs.\ GPU/\texttt{cudf-polars C3} and $2.60\times\text{--}3.63\times$ vs.\ simple heuristics \texttt{H1--H5}) and multi-scale spill regimes (\textbf{R4}, $\text{SF}\ge 10\text{ GB}$, saving $+470\text{ to }+5{,}408\text{ ms/q}$); and (iii) \textbf{Analytical PCIe Gen4/Gen5 Scope (Regime~R5)}: scaling bus bandwidth $B_{\text{bus}}$ from $5.69\text{ GB/s}$ (Gen4 $\times 4$) to $25\text{--}64\text{ GB/s}$ (Gen4/Gen5 $\times 16$) reduces $\Phi_{\text{PCIe}}(B_{\text{bus}}) = \frac{V_{\text{post}}/B_{\text{bus}}}{V_{\text{post}}/B_{\text{bus}}+T_{\text{kern}}}$ from $34.7\%$ to $10.8\%\text{--}4.5\%$, shifting the GPU crossover threshold downward by $3.2\times\text{--}5.8\times$, which $m=5$ canary calibration adapts to in $0.21\text{ s}$.

\subsection*{Four-Node Multi-Scale Scan-Filter-Aggregation and Native GPU (\texttt{RAPIDS cuDF} \& \texttt{cudf-polars}) Validation ($\text{SF}=1, 10, 30, 100\text{ GB}$)}
To validate physical scaling across heterogeneous CPU and GPU memory hierarchies without confounding operator-coverage differences, we executed the canonical TPC-H \texttt{lineitem} scan-filter-aggregation pipeline across $\text{SF} \in \{1, 10, 30, 100\}\text{ GB}$ ($6.00 \times 10^{6}$ to $6.00 \times 10^{8}$ rows; $64$ real-execution runs, zero estimation) across our locked four-node hardware matrix, incorporating NVIDIA \texttt{RAPIDS cuDF} (\texttt{libcudf}~v26.06.00)~\cite{rapids2024cudf} and the Polars GPU engine (\texttt{cudf-polars}, Polars~v1.35.2) on an NVIDIA Tesla~T4 cloud node ($14.56\text{ GB}$ usable GDDR6 VRAM; Table~\ref{tab:v12_fournode_multiscale_cudf} and Fig.~\ref{fig:v12_fournode_multiscale_cudf}). Four architectural insights emerge:
(i) \emph{End-to-End \texttt{libcudf} vs.\ Post-Arrow \texttt{H2D+Kernel} Envelope}: \texttt{RAPIDS cuDF} and \texttt{cudf-polars} are measured end-to-end from ZSTD Parquet on disk to final scalar output, whereas PyTorch CUDA isolates post-Arrow \texttt{PCIe H2D + SIMT Kernel} execution. At $\text{SF}=1\text{ GB}$, GPU-native ZSTD Parquet decoding allows \texttt{RAPIDS cuDF} ($112.76\text{ ms}$, $3.43\text{ J}$) to outperform even post-Arrow PyTorch CUDA ($177.83\text{ ms}$) by $1.58\times$; at $\text{SF}=10\text{ GB}$ ($1$ chunk) and $\text{SF}=30\text{ GB}$ ($3$ chunks), end-to-end \texttt{RAPIDS cuDF} ($322.37$ and $1001.71\text{ ms}$) converges to within $2.6\%\text{--}3.5\%$ of the PyTorch \texttt{H2D+Kernel} envelope ($311.07$ and $1028.13\text{ ms}$), confirming that PCIe transfer and GDDR6 bandwidth govern the physical throughput ceiling;
(ii) \emph{Intra-Node Cloud Acceleration vs.\ Cross-Node Many-Core CPU Crossover}: within Node~4 (provisioned with 2 host Xeon vCPUs alongside Tesla~T4), offloading identical Polars LazyFrame plans from CPU (\texttt{engine="streaming"}) to GPU (\texttt{cudf-polars}) yields intra-node speedups of $2.85\times$ ($\text{SF}=1$), $8.18\times$ ($\text{SF}=10$), $9.50\times$ ($\text{SF}=30$), and $7.43\times$ ($\text{SF}=100$). Crucially, however, \emph{cross-node} comparison at $\text{SF}=100\text{ GB}$ demonstrates that unthrottled 22-thread Polars streaming on Node~2 ($4266.59\text{ ms}$) outperforms 10-chunk \texttt{cudf-polars} on Node~4 ($5279.66\text{ ms}$) by $1.24\times$ on identical \texttt{x86\_64} architecture (while Apple~M1 DuckDB reaches $4292.58\text{ ms}$ vs.\ $16005.55\text{ ms}$ on Node~2 DuckDB because the 6-column scan-filter-aggregation pipeline uses $\le 2.79\text{ GB}$ streaming state without disk spilling on either node, and M1's integrated ANS2 NVMe controller [$2.95\text{ GB/s}$] + $68.3\text{ GB/s}$ unified memory avoids the SATA/Gen3 SSD read bottleneck [$1.42\text{ GB/s}$] and 22-thread ZSTD row-group decompression lock contention incurred by DuckDB on Node~2; to prevent storage-controller confounding, cross-node CPU crossover against Tesla~T4 is anchored on Node~2 Polars [$4266.59\text{ ms}$] and Node~1 DataFusion [$4036.88\text{ ms}$]), while narrowing \texttt{RAPIDS cuDF}'s advantage ($3674.43\text{ ms}$) to $1.16\times\text{--}1.17\times$---directly validating our core thesis that accelerator superiority depends on host core allocation and PCIe chunking rather than holding universally;
(iii) \emph{Calibrated GPU Energy Telemetry}: across end-to-end GPU windows on Tesla~T4 ($70\text{ W}$ TDP), \texttt{RAPIDS cuDF} consumes $3.43\text{--}143.97\text{ J}$ ($P_{\text{mean}}=30.4\text{--}39.2\text{ W}$) and \texttt{cudf-polars} consumes $6.71\text{--}191.83\text{ J}$ ($P_{\text{mean}}=26.8\text{--}37.1\text{ W}$), whereas full-stage board energy logged during PyTorch runs ($19.31\text{--}1312.14\text{ J}$ in CSV) spans host PyArrow ZSTD decoding plus GPU execution (active GPU energy during the $3166.38\text{ ms}$ \texttt{H2D+Kernel} window at $\text{SF}=100\text{ GB}$ is $\approx 125\text{ J}$); and
(iv) \emph{Strict Numerical Equivalence}: all $64/64$ runs satisfy $\text{EX}=1.000$ ($\epsilon_{\text{rel}} \le 3.52 \times 10^{-13} < 10^{-9}$; Tesla~T4 \texttt{cuDF} SHA-256: \texttt{138f1023ca63bd7e...}, V12 master SHA-256: \texttt{b263176b4af7c4ae...}).

\subsection*{Threats to Validity and Fixed Four-Node Architectural Scope}
\noindent\textbf{Construct Validity (Timing and Power-Integration Boundaries):} Comparing custom tensor pipelines against native columnar engines requires explicit boundary separation. In Table~\ref{tab:v12_fournode_multiscale_cudf}, \texttt{DuckDB}, \texttt{Polars}, \texttt{DataFusion}, \texttt{RAPIDS cuDF}, and \texttt{cudf-polars} report end-to-end Parquet-to-scalar latency, whereas \texttt{PyTorch CUDA} isolates post-Arrow \texttt{PCIe H2D + SIMT Kernel} execution to expose raw transfer-versus-compute ratios ($\Phi_{\text{PCIe}}$). Similarly, \texttt{cuDF} ($3.43\text{--}143.97\text{ J}$) and \texttt{cudf-polars} ($6.71\text{--}191.83\text{ J}$) integrate Tesla~T4 power ($36.3\text{--}39.2\text{ W} \le 70\text{ W}$ TDP) strictly across the active GPU query window, whereas PyTorch full-stage board energy in our archival CSV ($19.31\text{--}1312.14\text{ J}$) spans host PyArrow ZSTD decoding plus GPU execution ($\approx 125\text{ J}$ active GPU energy during the $3166.38\text{ ms}$ \texttt{H2D+Kernel} window at $\text{SF}=100\text{ GB}$). Both boundaries are explicitly labeled in the archival schema (\texttt{Timing\_Boundary} and \texttt{Energy\_Boundary}).

\noindent\textbf{Internal Validity (Partitioning Layout, Compression, and Host vCPU Asymmetry):} At $\text{SF}=30\text{--}100\text{ GB}$, cloud disk quotas necessitate partitioned $10\text{ GB}$ ZSTD shards on Node~4 (and $3.5\text{ GB}$ memory-capped streaming on Node~3), including a $0.022\%$ row-count delta at Node~4 $\text{SF}=30\text{ GB}$ between three $\text{SF}=10$ shards ($179{,}958{,}156$ rows) and \texttt{dbgen(sf=30, children=3)} ($179{,}998{,}372$ rows). Every run is verified at $\text{EX}=1.000$ ($\epsilon_{\text{rel}} < 10^{-9}$) against the exact IEEE~754 FP64 DuckDB reference of its corresponding physical dataset. Moreover, because Node~4 pairs Tesla~T4 with a 2-vCPU cloud host, we report both intra-node speedups ($2.85\times\text{--}9.50\times$ across $\text{SF}=1\text{--}100\text{ GB}$; $7.43\times\text{--}9.50\times$ at $\text{SF}=10\text{--}100\text{ GB}$) and cross-node comparisons against 22-thread x86\_64 (Node~2) and 8-core ARM64 (Node~3) CPUs to prevent CPU-throttled baseline distortion.

\noindent\textbf{External Validity (Workload Generalization and Fixed Four-Node Hardware Boundary):} We intentionally lock our hardware evaluation to four orthogonal single-host/cloud archetypes---consumer x86\_64 + entry $4\text{ GB}$ dGPU (Node~1), many-core 22T x86\_64 CPU (Node~2), unified-memory $8\text{ GB}$ ARM64 SoC (Node~3), and cloud server $15\text{ GB}$ GPU (Node~4)---because they span the four principal memory-hierarchy regimes relevant to single-node analytical routing without requiring further hardware expansion. Strict scope boundaries apply: the 9-feature router ($\mathcal{R}_{\text{GBR-9D}}$) is trained and evaluated across the full 75-query multi-operator suite (joins, windows, aggregations, strings) on Node~1 at $\text{SF}=1\text{ GB}$, whereas the 64-run four-node multi-scale matrix ($\text{SF}=1\text{--}100\text{ GB}$) targets bandwidth-bound scan-filter-aggregation (\texttt{lineitem}). Distributed multi-GPU NVLink collectives, out-of-VRAM multi-table hash-join spilling, and non-NVIDIA SIMT backends (AMD ROCm, Intel XPU) remain future extensions.

\noindent\textbf{Conclusion Validity (Template-Isolated Routing and Near-Tie Regret):} Under leakage-free template-grouped cross-validation on the 6-engine suite, $\mathcal{R}_{\text{GBR-9D}}$ attains $57.33\%$ Top-1 accuracy, $76.00\%$ Top-2 accuracy, and $34.98\%$ mean regret while reducing overall mean latency to $54.92\text{ ms}$---outperforming standalone GPU Cold ($56.96\text{ ms}$), Polars ($82.47\text{ ms}$), and DuckDB ($183.74\text{ ms}$). Top-1 accuracy is bounded below unity because sub-millisecond and few-millisecond queries exhibit overlapping execution latencies across Rust/C++ columnar engines, where selecting the runner-up incurs negligible absolute millisecond penalty while avoiding severe tail-latency regressions.

\section{Conclusion}
\enlargethispage{1.5\baselineskip}
\vspace{-3pt}
We presented \textbf{AST-Route} (\texttt{frozen\_ast\_route\_v11\_gbdt\_model.json}, SHA-256 \texttt{f0e5f17c832472e3...}), a pre-execution, conformal-guarded multi-objective SQL routing framework delivering \textbf{three core scientific contributions}:
\begin{enumerate}[leftmargin=1.5em,itemsep=1.5pt]
    \item \textbf{Contribution 1 --- Empirical PCIe/VRAM Crossover Laws \& Three-Way Tail-Safety Decomposition:} Across four hardware archetypes ($\text{SF}\in\{1,10,30,100\}\text{ GB}$), three-way stepwise ablation proves that our pre-specified inner-fold nested-CV PCIe margin guard ($\hat{\tau}_{\text{guard}}^{(-k)}=8\%$) drives $-78.20\text{ pp}$ of the in-domain P95 tail-regret reduction (where a 2-engine $\{\text{Polars},\text{GPU}\}$ pool at $55.28\text{ ms}$ captures $98.7\%$ of the 6-engine gain at $\text{SF}=1\text{ GB}$), tier-stratified $90\%$ Mondrian conformal bounds reduce P95 regret under distribution/selectivity drift by $-48.60\text{ pp}$ ($p=0.0018$), and the oblique $\text{CSCI}(q)$ projection ($\operatorname{Var}(\text{CSCI}\mid D..C)=0$) prunes $-28.2\%$ of GBDT splits, lowers mean regret by $-5.40\text{ pp}$ ($p=0.0038$), and lifts zero-shot cross-schema Top-1 accuracy by $+4.0\text{ to }+7.5\text{ pp}$ (with TreeSHAP confirming $\hat{\sigma}=34.2\%$ and $\text{CSCI}=24.8\%$ importance).
    \item \textbf{Contribution 2 --- Evaluation Against Five Stronger GPU Baselines \& $G_{\text{total}}=42$ Template-Cluster Mixed-Effects Inference:} Under global Holm--Bonferroni multiplicity control ($M=4$ primary tests), AST-Route ($55.37\text{ ms}$ net at $8\%$ primary guard; $54.92\text{ ms}$ at $12\%$ secondary sensitivity) matches static GPU mean latency ($p_{\text{Holm}}=0.0048$), beats static CPUs by $1.49\times\text{--}3.35\times$ ($p_{\text{Holm}}=0.0084$), and cuts P95 tail regret by $2.17\times\text{--}2.77\times$ across Cold FP64 ($257.31\%\rightarrow 118.40\%, p_{\text{Holm}}=0.0136$), Pinned + 2-Stream Async Overlap FP64 ($189.40\%\rightarrow 86.20\%$), Pinned + Overlap FP32 ($154.20\%\rightarrow 72.40\%$), and RMM-pooled \texttt{NVIDIA RAPIDS cudf-polars C3} ($338.00\%\rightarrow 121.84\%, p_{\text{Webb}}=0.0042$), while identifying when Resident-VRAM warm caching ($22.25\text{ ms}$ at $\text{SF}=1\text{ GB}$) suffices without routing. Across $\mathbf{G_{\text{total}}=42}$ \textbf{independent template families ($N=312$)}, REML linear mixed-effects modeling confirms a $-62.06\text{ pp}$ regret reduction ($z=-57.37, p<10^{-15}$), and query-level Scope~1 NVML GPU sensor energy correlates with Scope~3 DC shunt telemetry at $\rho_{N=75}=0.9684$ ($p=1.4\times 10^{-45}$).
    \item \textbf{Contribution 3 --- Multi-Scale Router-in-the-Loop ($\text{SF}=10\text{--}100\text{ GB}$) \& Public Fleet Trace Generalization:} In multi-scale router-in-the-loop dispatch ($\text{SF}=10\text{--}100\text{ GB}$, where the $4.15\text{ ms}$ cold parse overhead is $<0.02\%\text{--}2.3\%$), AST-Route achieves $182.40, 448.65,$ and $1{,}142.80\text{ ms}$ on Node~1 ($5.21\times\text{--}7.61\times$ vs.\ DuckDB) and $90.91\%\text{--}95.45\%$ Top-1 with $0.00\%$ P95 regret on Node~4 Tesla~T4 ($\text{SF}=10/30\text{ GB}$), while 4-node $\text{SF}=100\text{ GB}$ execution with \texttt{RAPIDS cuDF} and \texttt{cudf-polars} ($2.85\times\text{--}9.50\times$ intra-node GPU speedups across $\text{SF}=1\text{--}100\text{ GB}$, $7.43\times\text{--}9.50\times$ at $\text{SF}=10\text{--}100\text{ GB}$) demonstrates cross-node crossover where 22-thread Node~2 Polars ($4{,}266.59\text{ ms}$) surpasses 10-chunk \texttt{cudf-polars} ($5{,}279.66\text{ ms}$). Zero-shot routing achieves $83.64\%\text{--}86.67\%$ Top-1 on multi-GB Official TPC-DS ($\text{SF}=1\text{ and }10\text{ GB}$) and $90.00\%\text{--}92.00\%$ Top-1 ($100\%$ Top-2) across $80$ public real-world and fleet trace queries (SDSS DR16, NYC TLC, and Amazon Redshift \texttt{Redset}~\cite{vanrenen2024redset}) at $\text{SF}=10\text{ GB}$.
\end{enumerate}
